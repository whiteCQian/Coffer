# 产品说明

更新时间：2026-10-14。本文维护 Coffer 的功能与行为约定；实现及验收状态见[进度与问题](进度与问题.md)。

## 1. 要解决的问题

Coffer 面向个人文件管理和小型私有部署，帮助用户集中保存文件、按内容查找、确认整理建议，并在操作失败或结果不合适时追溯和恢复。

基本流程是：**导入/上传 → 解析与 AI 建议 → 人工确认 → 归档 → 查找/取回**。未执行最终归档时，标签分析完成不等于整个整理任务完成。

## 2. 产品形态

- **Windows 桌面**：Electron 封装静态界面和本地后端，使用 H2 与受控本地文件库。当前是个人免登录模式，不提供管理员、注册或账号切换；不依赖 MySQL、Redis、MinIO。
- **服务器 Web**：浏览器通过 HTTPS 使用服务，MySQL 保存正式元数据，独立私有 MinIO 保存正文，多账号与管理员/普通用户分离。
- **飞牛 OS NAS**：复用 Web 发布与业务契约，使用自己的数据库、对象存储、账号、密钥和备份；仍需目标设备实测。

三个安装实例彼此独立，不自动同步数据，不共享文件库、数据库、bucket 或密钥。桌面个人模式与服务器账号模式共享业务实现，但用户入口不同。

历史阶段的桌面多账号验收只描述当时版本，不能用于解释当前个人桌面行为。

## 3. 用户与权限

### Web/NAS 普通用户

用户只能读取、搜索、处理和导出自己的文件及派生数据，包括摘要、标签、对话、引用、任务、整理预览和操作记录。身份和 owner 由服务端会话确定，不能通过请求参数、文件 ID、路径或模型输出指定。

登录、退出、密码修改和会话撤销由后端处理；不公开注册。会话变化时界面清空旧身份状态，迟到响应不能写回新账号页面。

### Web/NAS 管理员

管理员创建、停用、恢复、重置和删除账号，管理非内容型运行设置、统一向量配置及审计。应用层不向管理员开放普通用户文件名、正文、摘要、标签、搜索结果或对话。

删除账号需输入完整账号名确认，立即停用并撤销会话，随后后台清理对象版本、缓存和数据库关联数据；失败可重试。不能删除当前登录账号或最后一个可用管理员，删除中的账号不能重新启用。审计与已有备份继续按各自保留规则处理。

宿主机、容器、数据库和备份管理员属于可信基础设施边界。当前产品不承诺抵御具有这些权限的人读取磁盘数据；若需要用户持钥加密，应另行设计。

### Windows 个人用户

应用打开自己的个人文件库，内部 owner/旧 `users/<id>` 标识只用于既有引用兼容。只含一个业务账号的旧库可沿用标识；旧多账号库拒绝静默合并，需先备份并明确迁移。

个人模式仍保留进程能力令牌、受控原生桥、CSRF 和数据路径保护，免登录不等于向其他本地网页开放后台。

## 4. 文件保存与整理

### 保存入口

- Web 上传：保存独立正文及元数据，之后异步解析、分析和生成建议。
- 桌面选择/拖放：先显示收件箱目标与来源接管说明。用户确认后暂存；最终入库路径确认、元数据提交和正文校验通过后才删除来源。
- 未确认、失败、源文件变化或占用时保留来源；来源删除失败给出警告并停止自动重试。
- 旧版“复制并保留”导入不追溯删除来源；备份恢复后撤销尚未执行的外部来源删除授权。

文件名、逻辑路径和存储键由服务端生成并核对。目标冲突时保留双方，不静默覆盖、改名或认领他人的文件。

### 分析与确认

文本、PDF、Word 等走解析管道；图片按配置调用 Vision。AI 可生成摘要、标签、分类及命名建议，用户可以修改、拒绝或稍后处理。

标签确认只影响标签决定；当前正式归档使用整理预览与确认流程。预览不改变正式文件，最终确认后生成持久操作记录，执行成功才报告正式归档结果。

将“确认标签并归档”合成一步是近期 UX 建议，尚不能作为已完成行为描述；待决策事项见[UX 改进](进度与问题.md#ux)。

### 状态与恢复

上传、解析、归档、撤销、删除和工作副本操作均有任务或操作记录。成功必须能够核对数据库正式状态和实际正文，不能只以 HTTP 成功或某次模型回复作为依据。

失败保留重试、人工核对或恢复路径；未知结果不伪装成成功。版本变化、内容变化和占用导致冲突时，显示原因并保留用户后续修改。

## 5. 查找与取回

- 关键词/全文查找提供文件结果；MySQL FULLTEXT 不可用时可回退 LIKE。
- 自然语言对话可调用工具查找和读取当前用户文件，回答引用真实文件版本与原文位置。
- Hybrid 向量检索是可选补充；未配置、服务故障或查询超时时保留词法检索。
- 文件下载、预览与 Range 读取均通过后端鉴权，不把 bucket 或永久公开链接作为读取入口。
- AI 生成的文件 ID、名称和路径不是授权依据；实际归属、版本、大小与 SHA-256 仍需核对。

## 6. 模型设置与内容发送

### Chat

当前聊天无需逐文件内容授权；发送时自动固定当前已验证的 Chat 配置，可查找旧文件和新文件。owner、版本和正文校验仍然生效。

这项行为取代旧说明中“聊天也必须逐文件确认”的口径，不扩大管理员的内容访问权限。

### Vision 与向量

API 模式下，敏感或无法本地判定的内容在发送前仍需对应文件、版本、正文指纹和配置目标的授权。文件或端点变化后，旧授权不能用于新内容/目标。本地模式限定已配置的本地服务，不自动改走远端 API。

Web/NAS 用户配置个人 Chat/Vision；管理员统一配置向量地址、模型、维度和 Key，测试保存的连接后启用。普通用户只能查看可用状态、确认自己的内容目标及重建个人索引，不能管理向量 Key。

个人桌面没有管理员控制台，不将 Web 管理员配置步骤套用于桌面。能力是否可用以当前个人设置及后端返回为准，模型服务不构成桌面打开已有文件库的硬依赖。

地址、模型或维度变化会隔离不兼容旧索引，用户需重新确认目标并重建。管理员 Key 单独加密保存，不进入普通用户任务快照。

默认不记录模型请求/响应正文。普通错误提示和管理员运行视图不包含文件内容、对象路径、模型密钥或原始异常文本。

## 7. 编辑、撤销与备份

桌面编辑使用受控工作副本：外部应用保存并关闭后再提交新正式版本；原件已变化时拒绝覆盖，可另存或放弃。关闭/放弃需核对用户确认的副本 SHA-256。

归档撤销核对当前 revision、归档后状态和正文身份，恢复名称、路径、分类、摘要、标签状态及原内容等正式快照，并使派生索引失效/重建。发生后续修改时转为冲突或人工核对，不覆盖新修改。

备份是数据库、正文、密钥、标识和配置的一致恢复点；静态加密、完整校验后才报告成功。恢复到空的新目录/卷，拒绝以新空库替代缺失数据。Redis 和向量索引可以重建，不作为正文和业务记录的唯一存储。

本机加密快照不等于独立介质备份。卸载保留业务数据，密钥必须与数据库/文件库一起保管；升级失败回滚整套数据，而不只是替换旧 JAR。

操作步骤见[使用与部署](使用与部署.md)，历史覆盖范围见[验收索引](验收索引.md)。

## 8. 已采纳决策与变化

- **2026-09-25，范围与隔离**：确立三种安装形态、实例数据独立及服务器管理员内容隔离。避免将旧匿名数据猜测性归给新账号。
- **2026-09-26，存储决策修订（原 ADR-001）**：桌面采用本地文件库，Web/NAS 保留对象存储。共享 FileStoragePort 与恢复状态机，分别遵守文件系统和对象存储的提交/校验语义。
- **2026-10-11，桌面交互与个人模式**：当前桌面改为个人免登录文件库、两步初始化与明确来源接管；Web/NAS 多用户规则保留。
- **2026-10-14，当前工作区模型规则**：聊天自动固定配置、不逐文件授权；Vision/向量保留其敏感内容规则，服务器向量配置由管理员统一管理。发布与复验状态另行登记。

旧方案中的桌面 MinIO 镜像、跨实例同步、统一单用户服务器及所有形态都移除 MinIO 的描述已取消。

原选题材料和范围变更附件保存在本机[学术材料](../../Coffer资料/学术材料/)；论文和答辩应只描述实际完成及对应环境验证的能力。

## 9. 首发范围外

不提供跨实例自动同步、协作共享空间、共享库多主写入、集群 HA、完整 DLP、音视频分析、Web 正文在线编辑或 macOS/Linux 桌面安装包。单机文件库及单节点对象存储本身不构成高可用或异地备份承诺。

新能力和 UX 建议先写入[进度与问题](进度与问题.md)的待决策区，确认后更新本说明。
