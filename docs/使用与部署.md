# 使用与部署

更新时间：2026-10-14。普通操作在前，安装和维护在后。命令默认从仓库根目录执行；Web/NAS 工具命令在部署目录执行。能力及权限见[产品说明](产品说明.md)，尚未关闭的验收项见[进度与问题](进度与问题.md)。

## 1. 日常操作

1. 导入或上传文件，等待内容解析和 AI 建议；AI 不可用时查看任务提示，保留文件并按原因重试。
2. 在详情核对标签，必要时修改或稍后处理。标签分析“完成”不表示已经归档。
3. 需要正式整理时选择文件、生成整理预览，核对名称/路径/分类/摘要/标签，确认后查看操作结果。
4. 用关键词或“用 AI 找文件”查找；从结果查看、下载或打开工作副本。
5. 从操作记录核对失败、冲突和撤销。HTTP 请求成功不代表每个批次明细都已完成。

当前聊天发送时使用已验证的 Chat 配置，无需逐文件授权；Vision/向量的敏感内容规则仍保留。用户应按实际界面提示核对目的与发送目标。

Web 工作台上传后留在当前页面，按这次上传的任务显示“等待解析、正在解析、确认标签、完成”等状态；可直接采用建议标签，也可在工作台打开详情调整。完成结果保留至“收起已完成”，刷新可恢复本标签页中的上传记录。无任务时收起进度卡片。上传失败与“文件已保存但 AI 分析未完成”分别显示，避免把分析失败误认为文件丢失；标签确认完成不等同于已执行正式归档。

Web 文件右键菜单和详情“未归档”旁提供“归档”入口，复用当前名称、摘要、分类和标签，不重新调用模型。存在未确认建议标签时，先确认是否采用这些标签；解析中暂不可归档。操作受理后显示“正在归档”，执行成功后更新为“已归档”；失败可重试原任务，也可在操作记录查看原因。工作台用蓝色表示已解析、绿色表示已归档、灰色表示尚未解析，待确认标签和正在解析使用橙色提示。

### 模型与账号设置

Web/NAS 用户在设置页配置个人 Chat/Vision，保存后测试连接，再选用可用模式。本地服务地址必须从运行应用的环境可达；容器的 localhost 不是宿主开发机。

管理员在控制台统一保存向量地址、模型、维度、Key，测试已保存配置后启用。用户只有向量状态、内容目标确认与个人重建入口。旧 `COFFER_EMBEDDING_ENABLED`/`COFFER_HYBRID_ENABLED` 不再决定启用状态。

向量地址、模型或维度变化后，用户重新确认目标并重建个人索引；未配置、未启用或服务故障时仍可使用关键词/全文检索。管理员配置不授权其读取用户文件。

管理员删除账号需完整账号名确认。立即撤销会话，后台清理全部对象版本、缓存和关联业务数据；失败后按界面重试。当前登录账号、最后一个可用管理员受保护，历史备份不会因为删除账号立即消失。

## 2. Windows 安装与个人文件库

### 安装与首次打开

安装包包含 Electron、Vue 静态资源、桌面后端及捆绑 Temurin 21 JRE；用户无需安装开发工具或外部数据库/存储服务。

1. 核对实际安装包与同次构建的 `SHA256SUMS.txt`。当前包命名基于 0.2.1，文件名相同不代表源码/schema 相同，应同时核对 manifest。
2. 安装到空目录或已有 Coffer 程序目录，不能选业务数据/文件库目录；安装前关闭已有程序。
3. 两步引导选择推荐位置或其他磁盘，核对最终路径，点击“创建并进入”。默认 `%LOCALAPPDATA%\Coffer`；自选父目录内创建 Coffer 子目录。
4. 桌面是个人免登录文件库，不创建管理员或注册用户。初次 AI 配置不影响离线打开已有文件。

程序目录、业务库和窗口缓存分离；缓存/偏好默认 `%APPDATA%\Coffer-shell`。数据库、正文、密钥和标识在业务目录一起保管。已有库可“打开已有文件库”，备份可“从备份恢复”；缺失目录、数据库或密钥时拒绝创建替代空库。

### 新建与切换位置

启动页可重新选择已有库或空目录，也可从设置的“管理文件库”返回。新库与原库独立，不搬迁或删除原数据；取消、创建失败或健康检查失败保留原绑定。

新位置不能位于旧库、程序或缓存目录内。普通非空父目录仅在其 Coffer 子目录可用时继续；部分创建失败目录保留待核对，不反复覆盖初始化。已保存的选择优先于默认位置，重启继续打开所选库。

仅有一个业务账号的旧库可沿用内部标识；多账号旧库需备份迁移，程序不会自动合并为个人库。

### 本地接管与编辑

选择/拖放先展示收件箱目标，并明确提示接管会删除来源。用户确认暂存后，还需核对正式入库路径；元数据和台账提交、正式正文大小/SHA-256 与来源一致后才删除原路径。

未确认、入库失败、来源变化或占用时保留来源。删除失败显示警告并停止自动重试；恢复备份后未执行的外部删除授权失效。旧版复制保留的历史来源不追溯删除。

外部应用只打开受控工作副本。先保存并关闭 Word/Office 等应用，再回 Coffer 提交新版本；占用或 owner 文件会阻止保存/清理。正式文件有新修改时可另存或放弃，不能自动覆盖。关闭/放弃核对当前副本摘要，保留选项不会丢弃未提交内容。

### 更新、备份与异常

更新前关闭程序。需要迁移时启动页显示“更新文件库”，输入备份口令后“备份并更新”；在双锁下创建并读回加密回滚包，再执行 Flyway。包位于 `.upgrade-backups`，升级成功仍保留，失败恢复整套旧数据。

个人库从设置创建整套静态加密备份，启动页恢复到空的新目录。标准备份必须是独立物理设备或符合检查的网络目标；本机加密快照的 independent=false，不作为独立介质备份。不能把同一 SSD 的 C:/D: 分区当独立设备。

后台异常退出可重启恢复台账；正常关闭和主进程结束会关闭自己的 Java/H2。启动器只管理自己创建的实例/PID，不接管别的服务。卸载默认保留数据和密钥，重新安装可以继续打开。

离线维护关闭程序和外部编辑器后执行；口令由安全提示/stdin 输入，不写入命令参数：

```powershell
.\scripts\desktop-backup.ps1 -Action backup -InstallDirectory '<安装目录>' -DataDirectory '<现有库>' -DestinationDirectory '<已存在的独立备份目录>'
.\scripts\desktop-backup.ps1 -Action verify -InstallDirectory '<安装目录>' -Archive '<加密备份包>' -TargetDirectory '<已存在的私有校验目录>'
.\scripts\desktop-backup.ps1 -Action restore -InstallDirectory '<安装目录>' -Archive '<加密备份包>' -TargetDirectory '<不存在或空的新目录>'
```

无法证明整套一致或必需密钥/正文缺失时不提交恢复。恢复与升级操作优先使用当前程序的界面及对应版本维护工具，不对现有库手工执行初始化。

<a id="source-test"></a>
## 3. 源码测试与本机 Web

### 桌面程序连同后端

```powershell
.\scripts\start-desktop-test.bat
.\scripts\start-desktop-test.bat -CheckOnly
.\scripts\start-desktop-test.bat -PrepareOnly
.\scripts\start-desktop-test.bat -Rebuild
.\scripts\start-desktop-test.bat -DataDirectory 'D:\Coffer Test\data' -ShellDirectory 'D:\Coffer Test\shell'
```

Electron 使用随机 loopback 端口启动并管理捆绑 Java，不启动 MySQL/MinIO/Redis/Vite。默认测试库为 `%LOCALAPPDATA%\Coffer-desktop-test`，shell 为 `%APPDATA%\Coffer-shell-desktop-test`。

明确的源码测试模式只对空测试目录自动初始化；既有目录保留，安装版使用正常引导。静态资源、后端或 schema 更新时脚本重新准备；首次构建需 Node 22.12+、npm、JDK 17+、Maven，可用 `-NodePath/-NpmPath/-JavaPath/-MavenPath` 指定工具。

`-CheckOnly` 仅报告版本和资源状态，不启动应用。关闭桌面由启动器停止自己的后端；日志位于测试 shell 的 `launcher.log`，`test-startup-state.json` 不包含能力令牌。

### 仅桌面后端

```powershell
.\scripts\start-desktop-backend-test.bat -Port 8082
.\scripts\start-desktop-backend-test.bat -CheckOnly
```

独立默认数据目录 `%LOCALAPPDATA%\Coffer-desktop-backend-test`，默认端口 8080；控制台 Ctrl+C 停止。支持 `-JarPath/-JavaPath/-MavenPath/-PrepareOnly/-Rebuild`。占用端口时拒绝，不停止已有服务。

### 本机 Web 开发入口

```powershell
.\start-all.bat
.\stop-all.bat
```

此入口使用本机 prod 配置、MySQL、Redis/MinIO 配置和 Vite，只监听 loopback；不是生产容器部署或个人桌面安装方式。前端 `http://127.0.0.1:5173/`，后端健康端口 8080；prod 不开放 API 调试文档。

本地凭据由环境变量或被忽略的 `coffer-local.cmd` 提供。可配置 `JAVA_HOME/COFFER_JAVA_HOME`、`COFFER_DB_URL`、Redis/MinIO 的实际路径与数据目录；脚本不覆盖本机配置。

未设置其他 `COFFER_SECRET_KEY` 时创建根目录 `.coffer-encryption-key`；一次性管理员令牌 `coffer-initial-admin-token.txt` 在初始化后清除。日志 `logs/`，进程状态 `.coffer-runtime/`，停止入口只核对并停止记录的后端/前端 PID。

本机 HTTP 的 Cookie 配置不能用于公开部署；公开服务按下一节使用 HTTPS 和 Secure Cookie。首次安装依赖及重建需要相应网络/缓存。

<a id="web-nas"></a>
## 4. Web / NAS 正式部署

### 前置条件与边界

Linux Docker Engine、Compose 2.24+（含现有 5.x）、Python 3.10+、OpenSSL、GnuPG；对应 CPU 架构的镜像必须实际构建/验收。旧指南建议 4 核/8GB 是初始部署参考，不是已冻结的 NAS 容量承诺。

维护者提供域名、可信 TLS 完整链/私钥、AIStor 授权与支持证明；私有 CA 场景需客户端信任。固定镜像、授权/安全审查及卷权限由 preflight 检查。不能用测试 override、开发机旧 MinIO 或跳过证书校验作为生产准入。

只发布 HTTPS 443；MySQL/Redis/MinIO/backend 私网端口不发布，MinIO 控制台关闭。核对代理子网与 LAN/VPN/Docker 路由冲突，固定代理 IP 位于动态地址池外；只信任该代理覆盖的转发头。

MySQL 使用 TLS/VERIFY_IDENTITY，MinIO 使用 HTTPS 和独立 CA；代理到后台及可选 Redis 仍限受信单宿主私网。跨主机扩展先补 TLS 与边界验证。

### 首次安装

源码部署到 `/opt/coffer`，**以下命令在 `/opt/coffer/deploy` 执行**。使用受控 root/Docker 运维账号，Docker 权限等同宿主高权限：

```sh
python3 prepare.py --domain files.example.org --bind 10.0.0.20
install -o root -g 10001 -m 0440 /安全来源/fullchain.pem tls/fullchain.pem
install -o root -g 10001 -m 0440 /安全来源/privkey.pem tls/privkey.pem
install -o root -g 10001 -m 0440 /安全来源/minio.license secrets/minio.license
cp support-review.example.json evidence/support-review.json
# 负责人填写真实授权、支持、有效期、扫描及精确镜像记录
sh coffer.sh build --pull backend proxy mysql minio-init
umask 077
openssl rand -hex 32 > /root/coffer-db-ca-passphrase
openssl rand -hex 32 > /root/coffer-minio-ca-passphrase
python3 internal_tls.py --db-ca-passphrase-file /root/coffer-db-ca-passphrase --minio-ca-passphrase-file /root/coffer-minio-ca-passphrase
python3 preflight.py
sh coffer.sh pull minio
sh coffer.sh up -d --wait --wait-timeout 300
```

必须通过 `coffer.sh` 或受控 Python 工具同时加载 `images.lock.env + .env`，不能用裸 `docker compose up` 绕过锁定镜像或维护屏障。公网上线还需真实防火墙、TLS 及外部边界验收。

默认不启动 Redis；需要时 `sh coffer.sh --profile redis up -d --wait --wait-timeout 300`。缺少 Redis 可显示降级状态，但 SQL 检索、上传下载与数据库对话记忆可用。它没有持久卷，不保存正文或业务台账。

空卷初始化生成库范围的应用 DML 账号和独立迁移账号；一次性 migrate 执行 Flyway，后台不持有 root/DDL 口令。顺序为卷权限、数据库健康/迁移、对象存储初始化、backend readiness、HTTPS 代理；失败不放行。

每个部署独立项目名、代理网络、地址、secrets、卷及私有版本化 bucket `coffer-owned-v2`。应用仅拿受限子密钥，不能管理其他 bucket/用户；不要共享旧应用 root 凭据。

通过 HTTPS 设置首次管理员，初始化令牌来自 `secrets/admin_setup_token`，受控终端读取并输入。随后管理员创建普通账号；保存 `master_key` 并随整套加密备份保管。

### 目标环境验收

```sh
python3 acceptance.py --base-url https://files.example.org --initialize
# 仅隔离验收账号，配置并验证模型后继续
python3 acceptance.py --base-url https://files.example.org --exercise-failures
# 私有 CA 添加 --ca /安全来源/ca.pem
```

初始化创建管理员、两个账号及测试文件，状态凭据只存受限 `evidence/acceptance-state.json`。已有业务服务不得在没有维护窗口时跑初始化/故障演练。

deterministic 模型与 `compose.acceptance.yaml` 仅用于独立项目/卷的隔离测试，需显式测试环境；生产 preflight 拒绝测试配置。核心验收覆盖 HTTPS、两账号/管理员隔离、文件/对话、私有存储、卷权限、DDL 拒绝、Redis 降级/重建、存储故障与重启恢复；NOT_RUN 不是通过。

从非可信网络完整扫描真实入口，再验证报告：

```sh
nmap -Pn -sT -p- -oX external-ports.xml 实际公网IP
python3 external_boundary.py evidence/external-ports.xml --expected-ip 实际公网IP --outside-trusted-network
```

扫描需覆盖 65535 TCP、报告在两小时内且仅 443 开放；NAS IPv4/IPv6 分别检查，操作者确认实际扫描网络。宿主机上的检查不能证明外网不可达。

### 容量、健康与凭据

独立 UID 10002 sidecar 在实际 MinIO 卷 statfs，无网络/凭据、不能读取对象；后台只读独立容量收据。采样 10s，过期 30s 时拒绝新增写入/降低就绪，不用后台临时盘空间替代对象卷。

基线警告为 4GiB 或 10%，写入需保留 2GiB 或 5% 的较大安全储备并扣除预约增长；配额/并发以当前配置为准。流量超限、磁盘不足和账号配额通过固定 4xx/5xx 提示，不能改 ACL 或伪造收据消除告警。

密钥/证书宿主权限按工具实际核对，不依赖 Docker bind secrets 的 uid/gid/mode 声明。初始化配置、TLS、内部 CA、应用主密钥与实际镜像一并受限保管。

## 5. Web/NAS 整套备份、恢复与升级

使用持久维护屏障停止全部写入者，关闭原容器自动重启及 MySQL event scheduler；探针对全表、owner、台账、对象版本/SHA-256 和加密凭据取一致证明后，干净停止数据库/对象存储。

冷备份包含两卷、backend_state、secrets、TLS/internal-tls、配置、版本和精确镜像。MinIO 全卷含历史版本、删除标记及 `.minio.sys`；当前对象 mirror 不能替代。Redis/容量收据不备份。

```sh
umask 077
openssl rand -hex 32 > /root/coffer-backup-passphrase
python3 backup.py --passphrase-file /root/coffer-backup-passphrase
# 独立可信工作站、私人仓库和单独 GitHub 凭据
python3 offhost_github.py /安全暂存/coffer-ID.tar.gpg
```

GPG AES256 密文完整解密校验通过才恢复服务；离机 release 分片全部回读并核对分片/整包 SHA-256。密码不上传，独立离线保管。建议保留 7 日/4 周/6 月，删除前留至少一份已恢复验证的离机副本；超过 48h 缺有效回执告警，密码轮换保留旧密码直到旧备份保留期结束。

隔离恢复到空白 Linux 主机/独立新卷：准备同版本工具、密文和口令，复制 `.env.example` 并配置新项目名、域名、绑定地址和不冲突网络；**不要运行 prepare.py 生成替代原凭据**。

```sh
python3 restore.py /异机备份/coffer-ID.tar.gpg --passphrase-file /root/coffer-backup-passphrase
python3 preflight.py
```

先认证密文清单与原配置、加载保存镜像，再恢复原凭据/PKI及新卷。只启动数据库/对象存储，全部表/版本/指纹/owner/台账/密钥一致后撤销 SQL 会话、失效向量并重建 Redis，最后开应用。新域名需受控更换边缘证书并复验 HTTPS；内部 CA 与模型主密钥整体保留。

`evidence/restore-proof.json` 是存储证明，仍需原双账号 HTTPS 业务复验。`.active-compose.json` 绑定镜像和新卷，禁止手工删除绕过。

```sh
python3 upgrade.py --passphrase-file /root/coffer-backup-passphrase --candidate-image coffer/backend:候选发布 --candidate-web-image coffer/web:候选发布
python3 maintenance.py status
# 失败/中断保持屏障，以完整恢复点恢复另一组空卷
python3 maintenance.py recover /备份/coffer-ID.tar.gpg --passphrase-file /root/coffer-backup-passphrase
```

升级在 Flyway 前整套备份，候选失败回滚旧镜像、凭据及新卷，保留失败旧卷。不能只回退 JAR 或 Flyway repair；异常不无条件恢复服务，root 人工 Docker 操作同样遵守维护窗口。当前工具不自动扩容/清理旧卷。

## 6. 版本更新与替换

精确镜像与支持审查由 `images.lock.env`、Dockerfile 和 `support-review.json` 绑定。原发布审查记录不意味着最新工作区/任意目标已授权、无漏洞或获厂商支持。

现有流程要求每月检查供应商更新/安全公告；Critical 或已利用问题当天隔离、24h 评估、48h 按支持渠道修复/替换，High 七日处理。发布更新经依赖/SBOM/许可证审查、隔离构建、完整验收和整套恢复点后人工执行；不自动跟随 latest。

支持/授权失效时冻结新生产部署。替换 S3 服务需验证版本化、范围读取、用户前缀与私有鉴权，迁移保留版本及删除标记并建立 versionId 映射，更新台账/补偿引用；不能假定跨服务版本 ID 不变。原卷保留直到备份与恢复验证通过。

完整生产登记还需真实授权/审查、独立服务器与 NAS、外部边界、容量并发、独立可取得的密码及恢复演练，见[进度与问题](进度与问题.md)。

## 7. 常见故障

- **模型不可用**：先核对已保存目标、模式、连通与容器可达地址；保留关键词查找及文件读取，不换用未授权端点。
- **来源保留/路径冲突**：检查导入结果和目标预览，不手工覆盖或删除原件；版本变化后重新预览。
- **工作副本被占用**：保存并关闭外部应用，核对 owner 文件与锁；不要自动删除仍可能有效的锁标记。
- **已有库缺项**：保留错误和原目录，用完整恢复点恢复；不补造密钥、标识或空库。
- **readiness 失败**：核对实际存储、数据库、容量收据和未完成操作；liveness 正常不代表业务就绪。
- **升级中断**：保持维护屏障，用匹配的整套恢复点恢复；不绕过 journal 或直接改库版本。
- **源码资源过期**：先 `-CheckOnly` 看版本/schema，再明确构建；不能用旧安装包测试结果宣称新源码通过。
