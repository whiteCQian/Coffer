# AgentFS Nexus 需求与范围清单

> 盘点日期：2026-09-24；状态补记：2026-09-25。主要依据旧任务/交接文档、当前实现和问题手册。需求文档中的 Cofferer 是产品代号。最终范围以[ADR-001](./decisions/ADR-001-最终产品合同与存储架构.md)为准，实施计划见[最终落地执行计划](./plans/AgentFS最终落地执行计划.md)。

## 已完成需求

### 文件接入与管理

- 上传文件并登记元数据，提供列表、详情、重命名、分类调整、删除和失败重试。
- 解析 TXT、PDF、DOC、DOCX；图片通过 Vision 模型分析。解析与模型处理由异步任务执行并可查看进度。
- 对批量导入目录周期扫描，等待文件大小/修改时间稳定，以 SHA-256 去重，记录失败和退避重试状态。
- AI 生成摘要、分类、标签和归档建议；标签支持确认、拒绝及标签候选/联想。

### 检索与对话

- 按文件名、摘要和标签搜索；MySQL FULLTEXT 不可用时有 LIKE 降级。
- 可选 Embedding + Redis 8 Vector Set 混合检索；向量路径超时或不可用时返回词法结果。该功能默认关闭。
- Agent 可调用解析、标签、文件搜索等工具；对话记录落库、会话记忆存 Redis。
- 对话引用由实际检索工具收集，提供文件级信息和摘要片段；前端可打开文件详情。页码级引用未纳入第一版。

### 文件治理闭环

- 治理预览与正式文件元数据隔离；可重新生成、编辑名称/分类/摘要/标签、跳过、部分确认、全量确认或取消。
- 确认前检查文件版本、对象指纹和路径冲突；确认后批量执行归档并记录每个文件的操作状态。
- 操作台账支持批次/文件查询、JSON/CSV 导出、失败重试、单项或批次撤销、冲突检测和持久化补偿。
- 归档目标名用日期、分类和序号保留机制分配，处理并发同名目标。
- 重新分析确认后的正式标签集合替换问题，用户于 2026-09-25 确认已解决；相关路径继续纳入发布回归。

### 模型设置与运行

- Chat、Vision、Embedding 通过 Provider 抽象接入 OpenAI 兼容服务。
- 持久化的 API/本地模型运行模式互斥；模式切换前连通性验证，任务记录启动时模式快照。
- 设置页支持端点、模型名、密钥保存/脱敏、测试、更新和删除。模型密钥使用 AES-GCM 保存。

## 待规划 / 待实施需求

### 最终交付新增的强制需求

- Windows 桌面版、服务器 Web 版和 NAS 版均需交付；三种安装实例各自保存独立数据，不做自动同步。
- 每个实例支持多账号与管理员/普通用户角色隔离；管理员默认不能通过应用读取普通用户文件及其派生内容。当前单用户实现须升级，旧“无登录”验收口径不再适用。
- 三种形态均需完成正文与元数据的备份恢复、升级失败恢复和实际环境验收；文件引用需要能定位真实解析来源。
- 具体设计取舍、依赖顺序和验收门槛以[最终落地执行计划](./plans/AgentFS最终落地执行计划.md)为准。

### 第一版收尾任务

- **C17 轻量敏感文件提示**：按文件名、扩展名和解析文本识别证件、财务、Token、私钥等；说明内容按 API 或本地模型模式的处理边界。不是完整 DLP，不做自动脱敏。
- **C18 Docker Compose**：编排生产前端、后端、MySQL 和私有正文文件卷；Redis 是可选、可重建服务。MinIO 不随生产包或最终应用发布。
- **C19 完整集成与故障测试**：见上节。
- **C20 文档收尾**：见上节。

### 已确认、尚未实现的最终交付

Windows 桌面、服务器 Web 和飞牛 OS NAS 均须交付；各安装的数据彼此独立；每个实例都支持多账号及管理员/普通用户隔离。旧单用户 MySQL/MinIO 业务数据已备份，用户允许在切换前清理，因此不做 owner 猜测或数据回填。新的存储合同、权限边界和异常记录见 [ADR-001](./decisions/ADR-001-最终产品合同与存储架构.md) 与 [M0 盘点记录](./plans/M0-存量数据盘点与保护记录.md)。

### 另行设计的 Windows 桌面本地文件库

旧本地部署方案描述 Electron 和 MinIO 镜像，已被最终计划取代。当前前端仍是 Vue/Vite Web 项目，后端上传/查看/归档仍以 MinIO 为核心；三形态文件系统存储和桌面版均尚未实现。最终架构统一使用受控的私有文件系统适配器，并从最终应用中移除 MinIO。

### 其他后续能力

- 页码级或更细粒度的检索引用：来源定位已纳入最终交付 R24；跨文件语义高亮等高级能力仍待规划。
- 完整的数据备份、恢复和跨部署迁移流程：各实例备份与恢复已纳入最终交付 R35/R42；跨实例迁移暂不承诺。
- 视频、音频、压缩包、电子表格、演示文稿等格式处理；第一版明确不承诺这些格式的 AI 分析与自动归档。
- 敏感文件更细的处理策略、规则配置、DLP 或自动脱敏均不属于当前第一版承诺。

## 废弃、历史或明确不属于当前范围

- **旧 SQL 初始化入口**：`docs/archive/sql/fulltext_search.sql` 是历史参考，不能用于代替 Flyway 迁移或变更生产结构。
- **单用户与 MinIO 新部署设计**：旧验收标准的“无登录/单用户”和“Web/NAS 以 MinIO 为权威”的约定已被最终范围取代；MinIO 将从最终应用及发布依赖中移除。
- **绕开治理台账的旧自动归档流程**：`TagConfirmedEventListener → StorageArchiveService.archive` 仍在代码中，但当前治理规范要求“预览 → 确认 → 执行 → 台账 → 撤销”；旧路径需要收尾时移除或限制，不能扩展成新需求。
- **固定分类 UI 维度**：前端已下线该筛选/展示维度；后端仍保留分类枚举和内部归档目录语义。
- **音视频及其他未列格式的分析**：第一版验收标准明确不支持作为 AI 自动分析和归档输入；不是已承诺后又取消的需求，当前仅属范围外/后续候选。
- **桌面端和本地文件库主存储的当前状态**：只有方案与落地计划，没有 Electron、初始化向导或本地文件主存储实现，当前不能按已交付能力验收；最终交付要求见 R30–R35。

截至盘点日期，仓库没有一份正式的“已废弃用户需求”登记表。上面标成废弃/历史的是旧实现入口或历史技术路径；其余范围外能力应保留为“待规划/不在第一版”，不要混记为已废弃。四类需求状态与最终里程碑追踪见最终计划。
