### 3.2 样本清单

由开发侧准备真实可打开的文件，先记录名称、大小和 SHA-256，再交给验收人；不使用个人真实资料。

- **S01 TXT**：`海棠项目会议.txt`，写入“项目代号：HT-2026-001；讨论时间：2026-10-20；结论：准备秋季资料归档”。用于准确查找与引用。
- **S02 PDF**：可复制文字的虚构采购单，包含唯一订单号 `PO-TEST-2048`。用于正文解析和引用。
- **S03 DOCX**：虚构周报，包含“完成检索模块初验”等已知句子。用于解析及桌面编辑。
- **S04 PNG/JPG**：清晰的虚构票据或标牌，包含可核对文字“测试仓库 A 区”和号码 `IMG-7301`。不要预设像素级完全相同的模型回答。
- **S05 同名不同内容**：两个不同来源目录均有 `报告.txt`，正文分别含 `VERSION-A`、`VERSION-B`；两份摘要不同。用于确认双方不会被静默覆盖。
- **S06 中文长文件名和多标签**：用于 320/390 像素窄屏、换行和按钮可达性。
- **S07 大小边界**：受支持类型、内容有效、接近 32 MiB 和大于 32 MiB 的样本。记录实际字节，不用伪造扩展名当正常文件。
- **S08 异常样本**：单独准备损坏 PDF、不支持类型，以及来源占用/可控修改的测试副本。
- **S09 批量与负载集**：先 10 个功能样本，再准备 1 千/1 万条元数据或实际文件集做分层测试。仅元数据压测不能证明真实正文容量。

可使用 `Get-FileHash -LiteralPath '<实际样本路径>' -Algorithm SHA256` 核对 Windows 样本和下载副本。尖括号为待替换路径；开发侧应直接交付清单，让你无需手工重复计算所有文件。

## 5. 核心体验测试用例

以下每个 ID 是一个可复用场景。D/W 应分别记录，例如 `C01-D`、`C01-W`；失败重试的不同变体也分别记录。步骤可以由你操作，技术证据由开发协助。

### C01 · 保存、分析、一次确认归档

- **环境/前置**：D/W；S01，已验证模型配置，有内容发送授权。
- **步骤**：导入/上传→等待分析→查看摘要和标签→修改一个标签→确认归档→查看最近操作→下载或取回文件。
- **预期**：各阶段状态明确；确认后先显示受理/进行中，持久执行成功才显示已归档；保存的标签与修改一致；只有一个有效归档操作；取回 SHA-256 等于 S01。
- **证据**：任务/文件/批次 ID、最终状态截图、原件及取回 hash。摘要不要求逐字固定，但不能编造样本不存在的关键事实。

### C02 · AI 不可用时仅保存，并在恢复后继续整理

- **环境/前置**：D/W；开发侧准备未配置/未验证模型的测试状态；S01。
- **步骤**：尝试分析，选择仅保存→查文件/下载→配置恢复并验证→对同一文件重新分析→归档。
- **预期**：第一阶段明确“已保存但未分析/未归档”，普通名称查找与取回可用；不承诺此时全文/向量已可用；恢复后能继续，不能因重试无意新增第二个文件。
- **证据**：前后同一 fileId、正文 hash、状态变化。

### C03 · 多入口状态一致与刷新恢复

- **环境/前置**：D/W 的适用页面；分别准备待确认、归档中、归档成功、归档失败、仅保存后归档样本。
- **步骤**：在首页/列表/详情/操作记录查看同一文件→刷新或关闭重开→尝试收起已完成记录；Web 增加“分析完成但无待确认标签”的样本。
- **预期**：状态在约定延迟内一致；分析完成不被误作正式归档；失败仍有处理入口；刷新不会把进行中的操作重置为成功。上传记录清理不删除正式文件。
- **证据**：同一 ID 在不同页面的截图与时间。桌面不存在的 Web 上传区不强行测试。

### C04 · 重复点击、超时和批量部分失败

- **环境/前置**：D/W；10 个样本；开发侧准备同一请求重复送达、一个操作失败和“服务已接收但响应丢失”的场景。
- **步骤**：重复确认同一操作；在未知结果后按提示重试；批量归档中保留一个失败项，再只重试失败项。
- **预期**：同一幂等操作只有一个有效结果；不能因重复点击复制正文/重复归档；失败项保留，成功项不重复执行，受理/成功/失败数量准确。
- **证据**：请求幂等标识、fileId、操作记录和前后数量。这里测试同一操作重试，不要求系统自动去重所有独立上传。

### C05 · 关键词查找、AI 引用与零结果

- **环境/前置**：D/W；S01/S02 已分析并归档，Chat 可用。
- **步骤**：按文件名及可检索摘要/标签查找→询问“HT-2026-001 会议结论是什么”→打开引用→输入不存在的关键词，选择用 AI 查找。
- **预期**：结果可取回；回答引用对应文件版本和实际原文，不能伪造 ID/内容；零结果带入原问题但不自动发送；取消或 AI 失败后问题保留，普通查找仍可用。
- **证据**：问题、引用、对应原文及 fileId；无结果截图。只有正文含某个词、但名称/摘要/标签没有的情况应按实际检索合同评估，不把全文搜索误当已承诺的任意正文字符串匹配。

### C06 · LOCAL 与 API 模式分别完成重新分析

- **环境/前置**：D/W；两种模式均准备可用配置，S01/S04；LOCAL 服务从后端所在主机/容器可达。
- **步骤**：启用 LOCAL→详情单文件重新分析→列表批量重新分析→生成预览；再启用 API，重复以上步骤；综合校验时记录每种能力请求次数。
- **预期**：两种模式各自可用，授权目标与实际执行一致；LOCAL 不误报 API 模式冲突，也不偷偷回退远端；记录重复探测是否已优化。
- **证据**：模式与目标截图、受控服务请求记录。缺某种服务记“阻塞”，不借另一模式通过关闭此分支。

### C07 · 模型授权取消、复用及配置变化

- **环境/前置**：D/W；S04，准备两个可区分的受控目标，开发可观察请求。
- **步骤**：取消一次内容发送确认→核对没有向外发送；同一 Chat 配置连续对话→修改端点/模型或切换模式；再提交旧界面任务；对需授权的 Vision/向量文件改变正文或配置后重试。
- **预期**：取消不会授权后台发送；同账号同 Chat 配置可复用授权；变化后重新核对有效目标，旧快照/旧逐文件授权不可用于新内容或新目标；没有错误的“未授权自动降级”。
- **证据**：受控端点请求计数/配置版本与页面结果，日志不保存 Key 或正文。只观察弹窗不能证明没有网络发送。

### C08 · 文件限制、损坏和同名冲突

- **环境/前置**：D/W；S05/S07/S08，各变体分开执行。
- **步骤**：提交接近上限的有效文件、超限文件、损坏文档、不支持类型；将同名不同内容文件导入，并制造明确目标冲突。
- **预期**：上限内受支持文件按合同处理；超限/不支持明确拒绝；若损坏文件已经保存，显示“保存成功、解析失败”并可取回，不能伪报分析成功；目标冲突不静默覆盖双方；不能把这些错误全解释成 AI 不可用。
- **证据**：实际字节数、错误类型、保存状态、双方 hash 和数量。

### C09 · 标签编辑、分页与页面刷新

- **环境/前置**：D/W；S06，至少两页同名/同大小/同时间的数据；包含多个待确认标签。
- **步骤**：新增/删除标签→编辑摘要后折叠再提交→编辑时等待一次轮询→四种排序分别翻页→切到后台再回来。
- **预期**：用户草稿不被轮询覆盖，折叠编辑仍正确提交；静态数据集跨页无重复/漏项，同值排序稳定；后台页面不持续重复刷新，返回可见后更新。
- **证据**：提交内容、页面 ID 顺序及浏览器请求计数。并发新增导致的 offset 位移单独记录，不与静态排序混淆。

### C10 · 真实图片、窄屏与独立使用体验

- **环境/前置**：D/W；S04/S06；Web 320/390 像素与桌面 800×600，Windows 另测系统 DPI 125%/150%。
- **步骤**：真实 Vision 分析图片→核对主要文字/对象→修改建议并归档→检索取回；在窄屏完成标签移除、确认、翻页、查看末条操作；尝试仅用键盘完成主要动作。
- **预期**：图片实际被处理，建议能说明样本主要内容，明显误识别可编辑；核心按钮可见可达、焦点与弹窗可操作，长文件名不遮挡动作；用户知道当前文件是否已保存/已归档。
- **证据**：原图、识别结果、修订结果与截图/短录屏；连接探针不能代替此例。记录每张图的事实正确性，按执行前确定的样本质量标准判定。

## 6. 环境、异常和恢复测试用例

### 问题处理规则

- **立即停止相关验收**：正文损坏/丢失、错误删除来源、跨账号内容暴露、恢复失败或未知结果被标成功。保留现场，在副本上定位与修复。

- **可书面接受后排期**：不妨碍任务的轻微样式或性能优化机会；若超出已冻结目标，就不再属于可忽略优化。

## 8. 现有工具如何复用

- 源码/接口回归：[开发说明](开发说明.md)、[frontend/tests](../frontend/tests/)、[backend/src/test](../backend/src/test/)。

- 故障与工作副本：[verify-file-crash-recovery.ps1](../scripts/verify-file-crash-recovery.ps1)、[verify-local-governance.ps1](../scripts/verify-local-governance.ps1)、[verify-work-copy.ps1](../scripts/verify-work-copy.ps1)。
