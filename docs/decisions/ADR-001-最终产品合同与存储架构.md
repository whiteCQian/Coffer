# ADR-001：最终产品合同与存储架构

> 状态：已采纳（产品范围由用户确认；文件存储目标架构由项目计划采纳）
> 日期：2026-09-25；存储决策修订：2026-09-26（仅桌面移除 MinIO，Web/NAS 保留）
> 关联计划：[AgentFS 最终落地执行计划](../plans/AgentFS最终落地执行计划.md)

## 背景

旧文档把产品定义为单用户，并分别提出 Windows 本地文件库加 MinIO 镜像、Web/NAS 以 MinIO 为正文主存储。用户已确认最终必须交付 Windows 桌面、服务器 Web 和 NAS 三种形态；每个安装实例的数据彼此独立；每个实例支持多账号及管理员/普通用户隔离。用户确认重新分析后的正式标签集合问题已经解决。

MinIO 官方开源仓库于 2026-04-25 归档为只读仓库，现有本机 MinIO 二进制也早于其最终开源版本。Web/NAS 保留 MinIO 时，必须明确可获得的受支持版本、更新渠道、漏洞处置和替换预案；不能把当前旧二进制直接当成生产基线。[官方仓库状态](https://github.com/minio/minio)

## 决策

### 产品范围

1. Windows 桌面、服务器 Web、飞牛 OS NAS 均是必须交付和实机/环境验收的产品形态。
2. 三种安装实例各自拥有数据库、文件库、密钥、账号和备份，不提供自动同步、共享数据库或跨端协作空间。
3. 每个实例支持多个普通用户和管理员。普通用户只能访问自己的文件及派生数据；管理员负责账号和非内容型运行设置，不通过应用读取用户正文、名称、摘要、标签、预览、台账、搜索、引用、聊天或内容日志。
4. 管理员对宿主机、容器卷、数据库和备份具有基础设施权限；本合同不承诺抵御拥有这些权限的主机管理员。若未来要满足主机管理员也无法解密正文，须单独设计用户持钥加密。
5. 旧 MySQL/MinIO 单用户业务数据不迁入新账号体系。用户已允许清除这批数据；切换前必须保存并校验回滚快照，授权清除范围仅限 agentfs schema 的非 Flyway 业务行和确切的 agentfs-bucket。不清除工作区 H2/Redis 文件、其他数据库或 bucket，不删除 Flyway 结构版本，也不提前删除唯一备份。

### 目标存储架构

1. 三种形态共享 FileStoragePort 和业务操作状态机。Windows 使用受控本地文件系统适配器；服务器 Web 和飞牛 OS NAS 使用 MinIO 对象存储适配器。数据库保存元数据、所有者、逻辑路径、摘要、大小及 revision；业务层不直接依赖任一具体存储 SDK。
2. Windows 使用桌面生产 Profile 的 H2 与本地文件库；服务器 Web 和飞牛 OS NAS 各自使用 MySQL 与独立 MinIO 实例或独立部署的数据集。各安装实例独立部署、独立备份，不共享数据库、bucket、密钥或正文。
3. Redis 仅用于可清空/可重建的会话记忆与向量索引；缺少 Redis 不得阻止已有文件读取和人工治理。
4. 桌面安装包和桌面运行 Profile 不包含或启动 MinIO 服务，也不打包 MinIO SDK 或要求 MinIO 凭据。Web/NAS 发布包保留 MinIO 适配器及其独立运行依赖；旧单用户对象不进入新账号空间。旧数据完成快照与校验后，按用户授权在切换维护窗口清理准确的旧业务表和旧 bucket；回滚数据只保留在受限备份中。
5. Web 静态服务器不得直接公开 MinIO bucket。只有已鉴权、已校验所有权的文件流接口能读取内容；默认 7 天预签名 URL 不再作为用户内容访问入口。MinIO API/控制台只在受信网络开放，服务凭据使用最小权限并独立管理。

### 权限、导入和失败语义

- 身份和 owner 必须来自服务端会话，不能由请求 DTO、文件 ID、路径、模型或前端状态声明。
- 首次管理员由一次性初始化令牌创建；之后管理员可以新增、停用和重置普通账号，但不能查看用户内容。
- 旧数据若有残留只进入隔离/待清理区，不能默认归给管理员。
- 外部文件默认复制入库。仅在用户明确要求时才删除来源文件；跨卷移动不作为原子操作。
- 归档目标路径在确认前展示并锁定。冲突时拒绝执行，不能静默改名或覆盖。
- DB 与正文存储之间不假设分布式事务。每个写/移动/删除都先持久化操作意图，使用适配器对应的暂存/提交、内容校验、幂等恢复和对账；事实未核对前 UI 不显示成功。文件系统适配器使用同卷 staging/原子重命名；MinIO 适配器使用对象写入、校验、复制/删除及补偿状态。
- 模型内容发送前显示端点与隐私边界；敏感或无法判定内容默认需逐文件授权。默认不记录请求/响应正文。

## 存储安全约束

- 逻辑路径必须由服务端生成；对根目录做规范化解析与 containment 检查。拒绝符号链接/连接点逃逸、设备名、尾随点/空格、路径穿越和不受支持的路径字符。
- 写入通过同一卷 staging 文件完成大小与 SHA-256 校验、flush/持久化和原子 rename；冲突以 no-overwrite 语义失败。
- owner 命名空间只用于隔离和运维；授权仍由数据库与应用检查，不能把不可猜路径当作鉴权。
- Web/NAS 的 MinIO bucket 对每个实例独立，应用只使用其专属服务账号；对象 key 与 owner 的映射由服务端校验，不把 bucket 可达性当作授权。NAS 须在飞牛 OS 实机验证容器、持久卷、网络、权限、重启和对象读写。NFS/SMB 多主写入、集群 HA 和在线扩容不在首发范围内。
- 单机本地文件库和单节点 MinIO 均不自带异地备份或高可用承诺。发布必须有数据库与正文的一致性备份、恢复演练与容量告警。

## 取舍与影响

- 共用存储端口使业务规则、owner 校验、台账与恢复语义一致；桌面省去 MinIO 的服务、端口和凭据生命周期，Web/NAS 继续复用对象存储能力。
- 代价是维护两种存储适配器，并持续承担 Web/NAS MinIO 的版本、安全更新、备份和运维责任。单节点部署的磁盘仍是容量和可用性边界，不宣传集群容灾。
- MySQL 与现有 MinIO 里的旧数据已经盘点并备份，但用户决定不迁移旧 MySQL/MinIO 单用户业务数据；上线切换采用“快照、校验、停写、按白名单清理准确旧业务库与 bucket、空库初始化”的明确流程。工作区 H2/Redis 文件仍保留。新 Web/NAS 使用独立的新 bucket，不复用旧单用户数据。
- 若后续更换服务端对象存储产品，应替换 FileStoragePort 适配器，不能改变业务所有权、路径、摘要和操作台账合同。
