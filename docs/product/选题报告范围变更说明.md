# 选题报告范围变更说明

> 用途：把已提交选题报告、旧验收文档与最终产品合同之间的差异形成可追溯的补充说明。原 DOCX 为用户已有工作文件，本说明不覆盖或改写它。
> 更新日期：2026-09-26（存储决策修订）

原始选题报告已保留在本机 `docs/archive/legacy/`，最新报告保留在本机 `docs/product/`。公开代码仓库只保存本范围变更说明，不上传报告 DOCX 原件。

## 变更原因

仓库中的选题材料、第一版验收标准和旧桌面方案存在冲突：旧验收标准写单用户；部分报告把账号角色隔离列为后续工作；旧部署方案以 MinIO 作为 Web/NAS 正文主存储，并给桌面设计了 MinIO 镜像。用户现已确认最终交付同时包含 Windows 桌面、服务器 Web 和 NAS，三种安装各自独立保存数据，并且三种形态均须具备多账号和管理员/普通用户隔离。

用户另确认旧单用户业务数据可以直接删除。因此最终系统不需要把旧匿名数据猜测性地归到管理员或新用户；切换前完成已验证备份，记录并校验清除范围，再从空库初始化账号体系。

## 最终范围修订

| 主题 | 旧材料/旧实现口径 | 最终口径 |
|---|---|---|
| 产品形态 | 第一版本地或私有 Web 单用户 | Windows 桌面、服务器 Web、飞牛 OS NAS 均须交付 |
| 账号 | 单用户、无登录 | 每个独立实例支持多普通用户和管理员，默认拒绝跨用户访问 |
| 管理员隐私 | 未定义 | 管理账号，不读取普通用户文件及其内容派生数据；宿主机/数据库管理员仍属于可信基础设施边界 |
| 数据实例 | 部署形态间关系未清楚说明 | 桌面、服务器和 NAS 的数据库、文件库、密钥和备份完全独立，不自动同步、不共享空间 |
| 文件内容存储 | Web/NAS 以 MinIO 为权威；桌面再做 MinIO 镜像 | 三种形态共享受控 FileStoragePort；桌面以本地文件库为唯一正文存储且不依赖 MinIO；Web/NAS 各自以独立 MinIO bucket 为正文主存储，不与桌面同步 |
| 旧业务数据 | 可能继续沿用并假设一个用户 | 已备份的数据在切换流程中明确清理，不迁入新账号；Flyway schema 保留，唯一备份按保留策略管理 |
| 文件导入 | 允许移动外部原件 | 默认复制，校验完成后原件仍保留；删除来源必须由用户明确发起 |
| 文件冲突 | 序号分配后再处理 | 目标路径预览时固定；冲突阻塞，不静默覆盖或改名 |
| 内容发送模型 | API/本地模式可切换 | 对敏感或无法识别的内容，在模型请求发生前显示目标端点并获得本次授权；默认不保留正文日志 |
| ISSUE-001 | 历史待排查问题 | 用户确认“重新分析后的正式标签集合”已修复，只作为发布回归用例，不再列为待修 Bug |

## 存储方案变更依据

MinIO 官方开源仓库已于 2026-04-25 归档为只读，官方仓库可核验其生命周期状态：[MinIO 官方仓库](https://github.com/minio/minio)。Web/NAS 继续保留 MinIO，需要在正式发布前明确受支持版本、更新渠道、漏洞处置和替换预案；现有本机旧二进制不能直接作为生产基线。

最终方案统一业务存储端口并保留两种适配器：Windows 使用本机受控文件库；Web/NAS 使用 MinIO 对象存储，各实例独立部署。桌面文件系统操作需由 R20/R21 实现 containment、no-overwrite、内容校验、原子 staging/rename、持久化意图及崩溃恢复；Web/NAS 的对象操作需实现 owner 校验、内容校验、幂等补偿与对账。单节点部署不代表支持共享网络盘多主写入、集群高可用或跨站点复制。用户决定不迁移旧单用户数据；旧 MinIO bucket 只在清理维护窗口被快照/核验并按白名单处置，新 Web/NAS 使用独立 bucket，不保留旧对象兼容导入。

## 范围外项目

- 桌面、服务器、NAS 之间的同步；同一数据卷被多个部署实例共享。
- 用户间共享空间、公开注册、匿名访问或管理员内容浏览。
- 多节点并发写、集群 HA、NFS/SMB 多主模式；需要时另做 ADR 和验收环境。
- 音视频智能分析、完整 DLP、自动脱敏、Web 正文在线编辑。
- 以隐藏路径或前端过滤代替服务端 owner 鉴权。

## 对选题报告与答辩的处理

若选题报告已正式提交或备案，应将本文件与[最终产品合同 ADR](../decisions/ADR-001-最终产品合同与存储架构.md)作为范围变更附件提交指导教师/学院确认。答辩只描述已在 Windows、服务器 Web 和飞牛 OS 目标设备实测通过的能力；不得把计划、模拟 NAS 环境或本机成功启动写成已交付证据。论文架构图和部署章节应采用最终 ADR，不再沿用旧 MinIO 镜像设计。

## 待冻结的验收参数

- 飞牛 OS 已确定为 NAS 操作系统；具体设备型号、CPU 架构、内存、文件系统、容器运行方式与卷权限仍需实机勘察，并在 R01/R43 前冻结。
- 文件数、总容量、单文件上限、并发用户数、性能目标、RPO/RTO 应在目标硬件基准测试后冻结，不能在最终验收时临时降低。
- 账号初始化人、首次管理员凭据交付方式及生产端口由部署手册约定，不写入仓库明文。
