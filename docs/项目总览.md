# AgentFS Nexus 项目总览

> 盘点日期：2026-09-24；状态补记：2026-09-25。本文区分当前代码与最终目标。Cofferer 是部分需求文档使用的产品代号；仓库和应用名为 AgentFS / AgentFS Nexus。最终产品合同见[ADR-001](./decisions/ADR-001-最终产品合同与存储架构.md)，剩余任务见[最终落地执行计划](./plans/AgentFS最终落地执行计划.md)。

## 1. 项目目标与核心业务

AgentFS 的最终目标是面向个人/小型部署环境的多账号 AI 文件管家。它解决文件散落、难以按内容检索、人工归类成本高，以及自动化操作不透明、出错后难追踪或撤销的问题。**当前代码仍是缺少正式认证隔离的单用户实现**，不能据此公开部署；多账号和三个目标安装形态尚未落地。

系统通过统一文件入口保存元数据和文件对象，异步解析文档/图片，调用可配置的 AI 模型生成摘要、分类、标签和归档建议。治理建议先进入独立预览区，由用户检查、修改、跳过或确认；只有确认后才执行归档，并把每个文件的操作及撤销状态写入台账。用户也可以通过关键词或自然语言查找文件，并查看 AI 回答引用的真实文件来源。

核心闭环：

```text
上传 / 收件箱导入 → 异步解析与 AI 分析 → 整理预览 → 用户确认
      → 对象归档与元数据更新 → 操作台账 → 查询 / 重试 / 撤销
```

## 2. 技术栈与运行环境

| 部分 | 当前配置 |
|---|---|
| 后端语言与框架 | Java 17 编译目标；Spring Boot 3.5.13；Spring MVC、Spring Data JPA / Hibernate、Validation、AOP、Retry、Actuator |
| 本机开发环境 | README / 代码 Wiki 记载 JDK 25 编译；JDK 17+ 可运行。Maven 3.9.x |
| AI 编排 | LangChain4j Starter 1.18.1-beta28、核心库 1.18.1；AiServices、`@Tool`、ChatMemory |
| 模型适配 | Chat、Vision、Embedding Provider；OpenAI 兼容 API。默认云端端点包括 DeepSeek、DashScope Qwen-VL；本地模式默认 Ollama 兼容端点 |
| 文件解析 | PDFBox 3.0.8；Apache POI 5.5.1（DOC/DOCX）；TXT 解析；图片交给 Vision 模型 |
| 对象存储 | MinIO Java SDK 8.6.0；OkHttp 固定 4.12.0 |
| 数据与缓存 | Spring Data Redis / Lettuce；Redis 8 Vector Set；开发 H2 文件库、测试 H2 内存库、生产 MySQL 8 |
| 数据迁移 | Flyway；H2 和 MySQL 分开维护 V1–V14；Hibernate 只校验表结构 |
| 接口文档 | Springdoc OpenAPI 2.8.17、Knife4j 4.3.0 |
| 前端 | Vue ^3.5.13、TypeScript ~5.7.3、Element Plus ^2.9.1、图标 ^2.3.1、Pinia ^2.3.0、Vue Router ^4.5.0、Axios ^1.7.9、Vite ^6.1.0、Vue 插件 ^5.2.1、vue-tsc ^2.2.0、openapi-typescript ^7.13.0；具体解析版本见 `frontend/package-lock.json` |
| 前端运行环境 | Node.js 20+、npm；Vite 开发服务器 |

Maven 中由 Spring Boot BOM 管理的 H2、MySQL Connector/J、Redis 等依赖未在 `pom.xml` 单独锁定版本。前端依赖大多使用 semver 范围，实际安装版本由 lockfile 决定。

### 当前 Profile 与外部依赖

- `dev`（默认）：H2 文件数据库 `./data/agentfs`，启用 H2 Console；重启后保留数据。
- `test`：独立内存 H2；Flyway 加载 H2 迁移。
- `prod`：MySQL `localhost:3306/agentfs`；需设置 MySQL 凭据。`start-all.bat` 使用此 Profile。
- Redis、MinIO 在默认配置中指向本机。Redis 向量检索和 Embedding 默认关闭；收件箱扫描也默认关闭。
- API 模型密钥由设置接口加密存入数据库。生产必须提供 `AGENTFS_SECRET_KEY`；本地启动脚本会创建被 Git 忽略的 `agentfs-local.cmd` 保存此密钥。
- Electron、独立桌面 Profile、以本地文件系统为正文权威的三个生产适配，以及 Docker Compose 均是计划内容，不代表已经实现。
- 当前源码仍以 MinIO 为主存储，旧代码和配置不能直接视为最终部署架构。新方案要求桌面、服务器 Web 和 NAS 使用各自独立的受控文件卷；MinIO 将从最终应用和生产依赖中移除，旧业务数据备份后在切换维护窗口清理，见 [ADR-001](./decisions/ADR-001-最终产品合同与存储架构.md)。

### 端口

| 端口 | 服务 | 说明 |
|---:|---|---|
| 5173 | Vite 前端 | 开发服务器；`/api` 代理到 8080 |
| 8080 | Spring Boot 后端 | REST API、`/doc.html`、`/v3/api-docs`、`/actuator/health` |
| 3306 | MySQL | 生产 Profile |
| 6379 | Redis | ChatMemory 和可选向量存储 |
| 9000 / 9001 | MinIO | 对象 API / 管理控制台 |
| 11434 | Ollama | 本地模型默认端点，可配置；非系统强制依赖 |

仓库根目录的 `start-all.bat` / `stop-all.bat` 是目前的一键启动入口；脚本会启动本机 Redis、MinIO、以 `prod` Profile 运行的后端 JAR 和 Vite 前端。路径在脚本顶部配置，MySQL 由用户预先准备。

## 3. 模块列表与职责

### 后端

| 模块 | 主要职责 |
|---|---|
| `file` | 文件 API、上传登记、查询与生命周期、解析器、MinIO 访问、文件状态和领域模型 |
| `inbox` | 周期扫描导入目录、稳定性检查、SHA-256 去重、失败重试和导入进度 |
| `governance` | Dry-run 预览、建议编辑/跳过/确认、批量归档、操作台账、撤销、失败补偿和归档对象命名 |
| `tag` | 标签候选、确认/拒绝、标签查询和标签持久化；仍含历史事件归档旁路 |
| `task` | 上传后异步处理任务、进度、重试和首页任务概览 |
| `agent` / `tool` / `service` | Agent 编排、文件解析/搜索/标签工具、对话和检索等跨领域服务；`service` 仍有历史兼容职责 |
| `model` / `model.runtime` | Chat、Vision、Embedding Provider，API/本地运行模式，端点路由与连接测试 |
| `vector` | Redis Vector Set 适配、索引更新协调、重建和清理监听 |
| `memory` | Redis 上的 LangChain4j 会话记忆 |
| `controller`、`dto` | 对话、搜索、设置、健康检查和向量运维等接口与传输对象 |
| `config`、`aspect`、`exception`、`util` | Spring/基础设施配置、模型调用日志、统一异常处理及通用工具 |

### 前端

| 目录/页面 | 职责 |
|---|---|
| `views/HomeView.vue`、`FilesView.vue` | 首页概览、文件列表、上传与批量选择 |
| `views/GovernancePreviewView.vue` | 浏览和编辑整理建议、跳过、确认、重试归档 |
| `views/OperationsView.vue` | 操作台账筛选、查看、导出、重试补偿和撤销 |
| `views/SearchView.vue`、`layout/ChatDock.vue` | 文件搜索、自然语言对话和引用卡片 |
| `views/SettingsView.vue` | API/本地模式、Chat/Vision/Embedding 端点和密钥设置 |
| `api/` | Axios 客户端、分域 API 封装；接口类型来自 OpenAPI 生成的 `api/generated/schema.ts` |
| `components/`、`layout/`、`stores/`、`utils/` | 文件卡片与详情、布局/上传/进度区、Pinia 视图状态及展示辅助 |
