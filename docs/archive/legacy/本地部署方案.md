# Cofferer Windows 本地部署方案

> **已废止的历史方案。** 桌面 MinIO 镜像和桌面/Web/NAS 之间的同步设计已取消；Web/NAS 保留 MinIO 正文主存储，但必须按当前多账号隔离、独立实例和运维合同实施。本文其余旧步骤仅供设计追溯；以[ADR-001](../../decisions/ADR-001-最终产品合同与存储架构.md)与[最终落地计划](../../plans/AgentFS最终落地执行计划.md)为准，不得据此部署或删除数据。
>
> 本文记录 Cofferer 第一版 Windows 本地部署节点的目标架构、文件生命周期和边界。它是对现有 Web / NAS / 服务器部署方式的补充，不改变系统已有的 API / 本地模型互斥规则。

## 1. 方案结论

Cofferer 保留两类部署方式：

1. **Web / NAS / 服务器部署**：继续以 MinIO 对象存储为文件本体的权威存储，浏览器通过 HTTP 访问文件内容。
2. **Windows 桌面本地部署**：使用 Electron 封装现有 Vue 前端，由 Electron 自动启动本地 Java 后端、数据库和 MinIO；本地管理文件库作为文件本体主存储，MinIO 作为镜像和统一对象访问入口。

桌面节点不是另起一套业务系统，而是复用现有前端、后端接口、数据库模型、AI 分析、预览确认、归档、台账和撤销能力，只增加本地文件访问与本地存储编排能力。

## 2. Windows 桌面节点组成

第一版只支持 Windows，不支持 macOS 和 Linux 桌面端。

桌面安装包包含以下组件：

- Electron：负责桌面窗口、前端资源加载、本地路径访问和子进程生命周期管理。
- Vue 前端：复用现有 Web 前端页面和接口调用方式。
- Java 后端：负责业务流程、数据库、AI 调用、文件治理、操作台账和补偿任务。
- 本地数据库：保存文件元数据、标签、预览、操作台账、任务和索引状态。
- 本地 MinIO：保存与本地管理文件库对应的对象镜像，并继续兼容现有对象存储抽象。

Electron 启动时自动启动 Java 后端和 MinIO，等待后端健康检查通过后再打开前端页面；退出时负责停止由本次桌面会话启动的服务。用户不需要手动执行多个启动脚本。

## 3. 本地文件库

### 3.1 文件库选择

首次启动时由用户选择一个本地管理目录。第一版要求该目录为空：

- 不自动扫描并导入目录中已有文件。
- 不把已有文件当作历史系统数据迁移。
- 如果目录非空，提示用户选择空目录或清理后重新配置。
- 文件库路径写入本地配置，后续由应用统一管理。

用户从系统外选择文件导入时，文件必须进入本地管理文件库；系统允许移动文件，不保留一份长期的外部副本。导入过程先进入受管控的收件箱/临时区，完成稳定性检查和登记后再进入 AI 分析与整理预览。

### 3.2 本地文件库是桌面模式主存储

桌面模式下，本地管理文件库是文件本体的主存储，MinIO 是镜像存储：

```text
用户选择外部文件
    -> 移入本地管理文件库的收件箱
    -> 登记、稳定性检查、AI 分析
    -> Dry-run 预览与用户确认
    -> 移动到最终分类/日期目录
    -> 同路径对象写入 MinIO
    -> 更新数据库、索引和操作台账
```

最终归档文件在本地文件库中的相对路径与 MinIO 对象 Key 保持一致，例如：

```text
本地文件库\contracts\2026\09\21\000-采购合同.txt
MinIO 对象 Key：contracts/2026/09/21/000-采购合同.txt
```

这里的 MinIO 路径指桶内的对象 Key，不是 MinIO 服务内部的 `data` 目录。应用不得直接修改 MinIO 内部磁盘布局。

### 3.3 新文件命名

新归档对象在当日分类目录下使用三个大写十六进制字符区分同名文件，范围为 `000` 到 `FFF`，扩展名统一使用小写：

```text
contracts/2026/09/21/000-采购合同.txt
contracts/2026/09/21/001-采购合同.txt
...
contracts/2026/09/21/FFF-采购合同.txt
```

序号只在同一日期、同一分类目录和相同原始文件名的命名范围内递增。序号分配必须由后端保证并发安全，不能由前端自行计算。

历史 MinIO 中使用 UUID 命名的对象不得自动迁移、重命名或清理。旧单用户业务数据现已由用户授权在切换维护窗口中清理，但执行前仍需完成备份校验、清理清单和明确的目标范围；不得据此直接操作 MinIO 内部 data 目录。最终应用不保留旧对象导入适配器，旧 bucket 按 M0 清理流程整体处置。

## 4. MinIO 同步策略

### 4.1 第一版只做单向同步

第一版同步方向固定为：

```text
本地管理文件库 -> MinIO
```

不实现桌面节点与服务器/NAS 之间的双向正文同步，也不把 MinIO 的变更反向覆盖本地管理文件库。Web / NAS 部署继续保留现有 MinIO 主存储方式。

### 4.2 同步失败处理

本地文件进入管理库成功后，即使 MinIO 镜像写入失败，也不删除或破坏本地文件：

- 本地文件仍可查看和使用。
- 数据库记录同步状态、失败原因和重试次数。
- 后台补偿任务按退避策略重试 MinIO 写入。
- MinIO 同步完成前，Web / NAS 端不承诺能够看到该文件。
- 同步成功后再更新可供远程访问的状态。

本地文件库、数据库和 MinIO 之间的最终一致性通过同步状态和补偿任务体现，不以静默覆盖或丢失文件换取“表面成功”。

## 5. 文件查看与编辑

### 5.1 桌面端查看

桌面端查看文件时直接读取本地管理文件库，不从 MinIO 下载，也不额外生成一份长期缓存。浏览器页面仍可复用现有 HTTP 接口，但后端在桌面模式下应将本地文件流直接提供给前端，避免先从 MinIO 取回再写一份临时文件。

### 5.2 桌面端编辑：工作副本 + 明确保存同步

采用“只读查看、工作副本编辑、明确保存并同步”的方式：

1. “查看”只打开本地文件的只读副本。
2. “编辑”创建工作副本，外部 Word、Excel 等程序只能修改工作副本，不能直接修改管理库原文件。
3. 用户点击“保存并同步”后，系统检查原文件版本、大小、修改时间和内容指纹是否仍与编辑开始时一致。
4. 校验通过后写回本地管理文件库，并同步到 MinIO。
5. 写回成功后生成新版本，重新分析内容并更新标签、摘要、检索索引和向量索引。
6. 如果原文件已被其他流程修改，拒绝覆盖并提示用户处理冲突。

第一版不支持 Web 端直接编辑文件正文。Web 端继续提供下载，用户修改后作为新文件重新上传；后续可以增加在线预览，但在线预览不等于允许直接修改原文。

## 6. 与现有部署方式的关系

| 场景 | 文件主存储 | 文件访问 | MinIO 角色 | 正文编辑 |
| --- | --- | --- | --- | --- |
| Web / 服务器 | MinIO | 浏览器通过 HTTP 流访问 | 权威对象存储 | 不支持，下载后作为新文件上传 |
| NAS | MinIO | 浏览器通过 HTTP 流访问 | 权威对象存储 | 不支持，下载后作为新文件上传 |
| Windows 桌面 | 本地管理文件库 | 直接读取本地文件 | 单向镜像 | 工作副本编辑，用户明确保存并同步 |

浏览器无法因为前端运行在网页中就直接获得服务器或 NAS 的本地文件路径权限，所以 Web / NAS 模式通过 HTTP 传输文件流是必要的；这不表示系统会在服务器磁盘上额外保留一份永久下载文件。只有 Windows 桌面模式可以通过 Electron 的本地能力绕过这次重复传输。

API / 本地模式仍然只表示 AI 模型请求的目标端点，和 Web / NAS / Windows 桌面部署形态是两个独立维度。无论部署形态如何，API 与本地模式都只能启用一种，任务必须记录启动时的模式快照，运行中不能静默切换。

## 7. 第一版边界

第一版本地部署明确不包含以下能力：

- macOS、Linux 桌面安装包。
- 选择非空目录后自动导入已有文件。
- 历史 UUID 对象自动迁移或重命名。
- 桌面节点和 Web/NAS 节点之间的双向正文同步。
- 自动合并跨设备正文冲突。
- Web 端直接修改文件正文。
- 直接操作 MinIO 内部 `data` 目录。

## 8. 建议落地顺序

1. 增加本地文件库配置、空目录校验和启动健康检查。
2. 将桌面导入流程接入现有登记、稳定性检查、AI 分析和 Dry-run 链路。
3. 增加“本地文件库 -> MinIO”的对象镜像、同步状态和补偿任务。
4. 统一本地相对路径与 MinIO Object Key，并接入三字符十六进制序号分配。
5. 使用 Electron 启动和停止 Java 后端、数据库与 MinIO，复用现有 Vue 页面。
6. 增加只读查看、工作副本编辑、版本校验和“保存并同步”流程。
7. 补充本地导入、MinIO 失败补偿、服务重启恢复、编辑冲突和 Web/NAS 回归测试。

## 9. 验收标准

- 选择非空文件库时系统拒绝初始化，并明确提示原因。
- 从外部选择文件后，文件被移动到受管控的本地文件库，而不是长期保留在原位置。
- 分析、预览、确认和归档流程与 Web/NAS 模式使用相同的业务规则。
- 归档成功后，本地相对路径与 MinIO Object Key 一致，扩展名为小写，重名文件按 `000`～`FFF` 区分。
- MinIO 暂时不可用时本地文件仍可使用，系统能显示待同步状态并自动补偿。
- 桌面查看不产生第二份长期文件，编辑必须通过工作副本和“保存并同步”。
- Web/NAS 模式保持现有行为，不依赖桌面端本地路径。
- 历史 UUID 对象不被自动迁移，后续清理不影响新桌面模式文件。
