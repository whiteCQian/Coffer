# UX 最小交付：实现与本地验收

日期：2026-10-15，香港时间。范围为原《UX优化方案》第 11 节的七项最小交付。本次交付源码、本地构建与验证；没有创建 PR、替换在用桌面资源或发布服务器。

## 七项交付

1. **确认直接归档：已实现。** 新增 `POST /api/files/{fileId}/confirm-archive`。在文件锁和事务内采用当前名称、分类、摘要、标签及内容快照，复用现有持久归档执行器。确认不调用模型，也不新增内容发送授权。文件版本作为建议版本和幂等身份；重复提交返回原任务。已有归档、待处理归档或未完成撤销不能另起重复任务。原高级整理预览继续可用。
2. **整组标签与按需编辑：已实现。** 共用确认卡允许删除、新增标签，默认整组采用；名称、摘要、分类收在可选展开区。编辑后即使收起，也随“确认并归档”提交。单文件一个主操作；多文件按当前可处理选择显示准确数量，逐文件受理，失败项保留选择，成功项不重复提交。“稍后处理”关闭确认区，文件和建议留在库中。
3. **真实任务状态与保存降级：已实现。** 列表、详情、最近上传和待确认计数使用归档事实投影，区分已保存正在整理、待确认、正在归档、已归档、归档失败、需核对及正在撤销。增加仅保存入口；未授权分析时保存元数据和正文，不发起模型任务。AI 失败仍可查看、下载、按名称查找或按原名先归档。此时不承诺全文和语义索引已经可用。
4. **最近操作：已实现。** 首屏以文件名、时间、归档结果和可用动作呈现，可按文件名搜索、只看需处理项。批次查询、内部路径、导出和维护面板收在技术详情。保留原撤销与异常处理能力，撤销提示明确不恢复已移除的外部来源文件。页面提供整体滚动，记录和动作在窄布局可达。
5. **零结果承接 AI：已实现。** 文件库及原搜索页的零结果入口将原问题带入当前 AI 面板，无需换页重输，不自动发送。请求仍经过已有模型目标与逐文件内容授权边界。显示未配置或连接尚未确认的原因；发送失败或取消时保留问题，普通查找及下载继续可用。状态检查读取实际活动模式，兼容本地模型。
6. **桌面默认复制、显式移动：已实现。** 新 HTTP 原生导入请求的 `moveSource` 默认 `false`，复制不创建删除来源任务。每次新的选择／拖放恢复保留原文件默认值。主动移动才出现数量、文件名及移除来源影响的确认。新选择文件自动采用内部保存路径，保存后才请求可选的 AI 分析授权。来源移除继续复用已有持久状态机和来源／副本校验；失败或来源变化保留来源并显示警告。没有迁移、重放旧移动记录或批量改名。
7. **模型测试反馈：已实现。** 卡片保留测试时间、成功／失败／超时及下一步；按账号、能力和配置指纹保存在当前浏览器／桌面 Web 存储中，刷新可见，编辑、保存或删除配置会使相关结果失效。区分修改未保存、配置已保存、当前模式待校验、正在使用及连接测试通过。综合检查先并行显示单项结果，再执行既有服务端模式门禁；一个超时不会清掉其他结果。Vision 探针实际发送生成的虚构 PNG，不再仅发送文字；仍只表示连接探针通过，不代表实际图片整理验收通过。

## 验证证据及边界

### 桌面端：真实源码壳与临时文件库

`desktop/test/ux-mvp-e2e.cjs` 复制源码壳、最新前后端构建和已验证 JRE 到独立 `.test-tmp/ux-source-*` 目录运行；不改 `desktop/.build/resources` 或 `desktop/dist`。使用本地虚构模型服务及新建虚构 TXT。

- 实际走通：选择 TXT → 默认保留来源 → 同意该任务内容发送 → 自动建议 → 一次确认归档 → 按名称查回 → 读取下载字节与输入一致；名称未加内部编号。
- 实际走通显式移动：主动勾选、确认影响后导入，来源移除，库中内容可读取。移动后的下一次新选择再次默认保留来源。
- 实际检查 800×600 窗口、125%／150% Electron 页面缩放下最近操作末尾记录与撤销按钮可达。页面缩放不是更换 Windows 系统 DPI 的同义验收。
- 桌面持久服务用例另外验证来源变化、占用、跨用户目标、重复确认、来源移除警告等边界。
- 证据日志：`.test-tmp/ux-electron-complete.log`；每轮独立文件库目录由日志列明。隐藏窗口截图曾超时，最终桌面用几何与动作断言验收，没有把失败截图当作视觉证据。
- 当前机器的执行沙箱会阻止 Electron 安装目录的 AppContainer 读取；验收进程经执行环境提升运行，产品 `app.enableSandbox()` 保留，未改系统 ACL。

### Web 端：独立 HTTP 与布局验证

`SavedFileWebFlowTest` 在非桌面 Spring 测试上下文、隔离 H2 和确定性内存对象存储上运行真实控制器、事务、归档执行和下载接口：仅保存 → 文件库可查 → 一次确认 → 归档成功 → 重复提交同一任务 → 下载字节一致 → 按文件名查操作 → 跨用户访问拒绝。

该测试没有连接已部署服务器，也没有覆盖真实 MySQL／MinIO／反向代理链路。旧报告中的服务器实测证据不能替代新代码部署后的复验。

`scripts/verify-ux-mvp-ui.cjs` 对生产前端构建使用虚构 HTTP 响应，分别检查：

- Web 640、1024、1440 像素宽；桌面布局 800×600、设备比例 1.25／1.5。
- 默认建议、整组新增标签、编辑后折叠再提交，未进入第二次预览。
- 多文件 2 项受理 1 项、1 项失败，数量与结果一致，失败项仍选中。
- 零结果原问题进入 AI 输入框，尚未点击发送时不产生聊天提交。
- 最近操作末尾记录和撤销动作可滚动到达，技术信息默认折叠。
- 综合检查中文字结果先显示成功、图片结果超时；刷新后结果保留，单项失败及成功可重试，修改配置使旧结果失效。

全部五种布局组合通过。虚构页面截图在 `.test-tmp/ux-evidence/`，其中 640 像素最近操作截图已人工查看。此脚本是界面契约和布局验证，不能表述为真实云模型或服务器端到端验收。

## 复现方法

1. 使用 Java 17+ 与现有 Maven 缓存执行相关测试。此次机器使用 JDK 25；本地缓存读取需要执行环境提升，未下载依赖。相关测试类见上文，实际测试日志为 `.test-tmp/ux-regression.log` 及后续定向复测日志；以 `backend/target/surefire-reports/` 最终报告为准。
2. 前端检查：`node frontend/node_modules/vue-tsc/bin/vue-tsc.js -p frontend/tsconfig.app.json --noEmit`。
3. 准备 UI 测试构建：`node frontend/node_modules/vite/bin/vite.js build frontend --outDir ../.test-tmp/ux-web-build`。
4. 设置 `COFFER_PLAYWRIGHT_MODULE` 为本机 Playwright 安装目录，执行 `node scripts/verify-ux-mvp-ui.cjs`。脚本自行启动只绑定回环地址的临时静态服务；也可通过 `COFFER_UI_ORIGIN` 指向本地前端。
5. 构建 `backend` 的 `desktop` Maven profile 后，执行 `node desktop/test/ux-mvp-e2e.cjs`。需要现有桌面 JRE 资源、Electron 和三个允许的本地模型端口之一空闲。脚本使用新目录，不触及实际文件库。

## 剩余限制与发布步骤

- 原报告的桌面新文件流程证据边界现在补充为“最新源码壳＋虚构模型＋临时真实文件库通过”；不能外推为在用安装包或真实模型均已通过。
- 真实图片从识别、建议、确认、归档到查找尚需单独用虚构图片验收；文字查找和连接探针均不能替代。
- Web 生产链路、桌面安装／升级包、Windows 系统 DPI、真实断电中断，以及首次用户可用性实验仍需另行验收。现有异常服务测试不等于全部桌面崩溃点已经重跑。
- 模型测试历史保留在当前客户端，不是跨设备测试历史数据库；清理浏览器存储会移除。现有模式门禁会在单项均通过后再次校验保存配置，可能增加模型测试请求数；单项反馈仍保留。
- 桌面后续：备份实际库，使用 `scripts/build-desktop.ps1` 构建新资源／安装包，验证资源清单及包校验，使用隔离库完成安装升级、复制／移动、异常恢复和真实图片验收后，再单独处理在用程序替换。本次不需要新增数据库迁移。
- 服务器后续：备份数据库与对象存储，构建服务器 profile 和前端，部署到隔离测试版本，分别在真实 MySQL／MinIO 和普通账号下复验 TXT 存取、多文件部分失败、授权变化、归档重试、窄布局和图片，再单独安排发布及回滚验证。
