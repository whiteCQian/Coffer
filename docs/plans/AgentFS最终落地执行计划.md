## 0. 最终交付的定义

交付的是**一套共享业务核心、两种正式存储适配器、三种经过环境验收的部署形态**：

```mermaid
flowchart TB
  CORE[共同业务核心：身份/权限、文件治理、AI、搜索、台账、撤销] --> PORT[FileStoragePort 与可恢复操作状态机]
  PORT --> FS[本地文件系统适配：staging、校验、原子提交]
  PORT --> S3[MinIO 适配：对象写入、校验、补偿]
  FS --> WIN[Windows：Electron + 本地 Java + H2 + 本机文件库]
  S3 --> WEB[服务器 Web：Java + MySQL + 独立 MinIO]
  S3 --> NAS[飞牛 OS NAS：同一 Web 发布包 + 独立 MinIO]
  OLD[旧 MySQL 与 MinIO 数据] -. 已校验回滚快照 .-> SNAP[本机受限备份]
  OLD -. 用户授权：切换时清理准确旧库和 bucket .-> PURGE[一次性运维清理，不进入最终应用]
  WIN -. 数据独立、无自动同步 .- WEB
  WIN -. 数据独立、无自动同步 .- NAS
```

- **所有形态的共同能力**：多账号登录与隔离、文件导入/解析、AI 建议、预览编辑、确认归档、操作台账、单项/批次撤销、检索与真实来源引用、模型 API/本地模式、敏感内容提示、失败重试与恢复。
- **Windows**：本地文件库是文件正文的唯一权威存储；H2 使用独立生产 Profile；Electron 只承担窗口和本地服务生命周期。无需用户安装 JDK、Node、MySQL、MinIO。断网或模型不可用时，已有文件仍可读取和人工管理。
- **服务器 Web / NAS**：MySQL 保存正式元数据，MinIO 保存文件正文；每个安装实例使用独立数据库、bucket、凭据和持久卷。前端使用生产静态资源，后端与 MinIO 由容器/服务管理；两者使用同一套发布包，在服务器与飞牛 OS 实机分别验收。
- **账号**：管理员只管理账号与非内容型系统设置，默认不得通过应用查看普通用户的正文、文件名、摘要、标签、预览、台账、检索结果、引用、聊天与内容日志。普通用户只能访问自己的资源；不提供公开注册和用户间共享。
- **威胁边界**：上述“管理员不可读”指应用角色权限。拥有主机、数据库、备份或 Windows 文件系统权限的运维人员属于可信基础设施边界；若未来要求连宿主机管理员也无法读正文，应另立用户持钥加密项目，不可用现有明文解析架构承诺。
- **明确不交付**：桌面/Web/NAS 自动同步、协作共享空间、多实例同时写一个库、音视频分析、完整 DLP、Web 正文在线编辑、macOS/Linux 桌面包。

### 对原设计作出的更改

1. **单用户改为多账号。** 最新选题报告和本次确定的目标优先于旧 C01“无登录”定义；身份与隔离必须先于桌面存储和公开部署完成。
2. **仅桌面版移除 MinIO，Web/NAS 保留。** 桌面使用本地受控文件库，安装包和运行 Profile 不含 MinIO 服务、SDK 或凭据；Web/NAS 通过同一 FileStoragePort 的 MinIO 适配器保存正文，分别使用独立 bucket、持久卷和备份。官方开源仓库已归档为只读，参见[官方仓库](https://github.com/minio/minio)；R40 发布前必须落实可维护版本、更新渠道、漏洞处置与替换预案，不能直接沿用本机旧二进制。旧单用户数据不迁移；切换前快照与核验，维护窗口清理准确旧库和 bucket。
3. **导入默认复制。** 先将源文件复制到 staging、校验 SHA-256、完成登记，再让用户选择是否删除外部原件。跨卷“移动”不具备可靠原子性，不能作为默认无损导入动作。
4. **目标名称在预览中固定。** `000`–`FFF` 序号可用于分配候选路径，但最终路径必须在预览页展示；确认时锁定并复核。发生冲突时阻塞，不在确认后静默改名或覆盖。
5. **撤销恢复完整正式状态。** R22/R32 当前台账已保存归档前后的正式名称、路径、分类、摘要、标签状态/备注、revision 和正文指纹；撤销按版本完整恢复，并使派生索引失效/进入重建流程。可选向量索引与三部署检索一致性的目标环境验证仍归 R50/R51，不再按“仅恢复路径、名称和分类”的旧实现安排重复开发。
6. **把成功定义为数据库与正文的可核对状态。** 上传、分析、归档、撤销和删除都使用持久操作/任务记录、幂等键与启动恢复，不再仅依赖提交后的内存事件或“失败只记日志”。

### M2：共同业务可靠性、文件访问和可信 AI

**R20｜统一存储端口、路径与文件身份。依赖 M1。**

- 定义 FileStoragePort 的写入、范围读取、stat、SHA-256、复制/移动、删除、no-overwrite 和冲突检查；桌面由本地文件系统适配器负责，Web/NAS 由 MinIO 适配器负责。上传、解析、预览、归档、撤销和文件访问只依赖端口。MinIO SDK、MinioClient 与 BucketInitializer 仅留在服务端适配及 Web/NAS 配置中；构建时将该适配器及 SDK 排除出桌面发布包，桌面运行 Profile 不创建 MinIO Bean，也不启动或连接 MinIO。业务记录保存 owner、逻辑路径、内容指纹和 revision，不存桌面绝对路径或服务端 bucket 凭据。
- 桌面文件根目录由用户数据目录绑定；按 owner 隔离逻辑命名空间。统一逻辑路径规范，并在本地适配器处理 Windows 大小写、Unicode、尾点/空格、设备名、路径穿越、符号链接和连接点；检查规范化后的实际路径始终在配置根目录内。MinIO 适配器校验 bucket/key 的 owner 映射，不直接接受客户端对象 key。
- 桌面文件写入采用同卷 staging、长度/摘要校验、flush/持久化与原子 rename；跨卷移动拆成持久化的 copy-verify-commit-cleanup 流程。Web/NAS 对象写入、复制和删除使用内容校验、幂等步骤与补偿任务；不能把对象操作宣称为 SQL 原子事务。NAS 在飞牛 OS 实机验证 MinIO 容器与持久卷，不承诺 NFS/SMB 多主写或集群共享写入。
- 不保留旧单用户 MinIO Key 的应用内兼容读取；旧数据由 R02 清理，不迁入新 owner。新 Web/NAS 初始化独立 bucket。过渡版本不能在旧对象尚未完成备份/清理前发布。
- **2026-10-01 实施进展**：上传、解析、预览、治理与清理已接入统一 `FileStoragePort`；本地适配器校验 owner、路径、保留名和链接，写入经过同卷暂存、摘要校验、落盘与原子发布；真实 Windows Junction 父目录的逃逸写入测试通过。MinIO 适配器校验 owner key，并实现条件写入、Range、复制/移动和摘要删除。`stat` 对实际对象字节重新计算 SHA-256 和长度，不能只信任可过期的对象元数据；元数据与正文不符进入冲突。干净 `desktop` Profile 打包后已核对 JAR 不含 MinIO SDK、适配器或配置类，并在隔离 H2 用户目录启动，健康检查为 UP、首次初始化状态可读；服务端构建保留 MinIO。隔离的真实 MinIO 实例通过双 owner、冲突不覆盖、范围读取和摘要校验测试；飞牛 OS 容器及持久卷仍需目标机器验收。
- **完成判据**：三种部署均只能经鉴权接口读取正文；两个不同 owner 可有同名文件，同一 owner 的目标冲突不覆盖；恶意路径/链接/对象 key 不能越权；断电/进程强杀后操作可恢复或进入人工处理态。
