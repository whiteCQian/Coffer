# R26｜隐私、错误与运行状态收口

本轮完成日志与错误出口、运行采样、聚合告警、全库主密钥轮换和诊断保留策略。管理员仅接收固定状态码、建议动作、数值统计及密钥指纹；不会收到文件名、正文、摘要、对象路径、模型端点、模型名称、账号所属凭据或原始异常。

## 运行状态合同

- `/actuator/health/liveness`：应用进程是否存活，依赖故障不触发无意义的进程重启。
- `/actuator/health/readiness`：Spring 就绪状态与同一份运行采样共同决定。数据库、Redis、文件存储或已配置存储卷故障返回 HTTP 503。
- `/actuator/health`、`/health`：公开汇总状态，不包含组件、连接地址和积压详情。
- `GET /api/runtime/status`：普通用户读取固定依赖故障码与下一步动作，不包含全局数量、容量数值或告警历史。
- `GET /api/admin/runtime`：管理员读取组件、容量、连接池、后台积压和当前告警。
- `GET /api/admin/runtime/alerts`：管理员读取最近 100 条告警的开始、最近观测及恢复时间。查询失败返回 503，不能解释为空历史。

首次采样延迟 2 秒，随后每轮完成后间隔 30 秒。健康采样使用独立的单线程调度器，不会被业务恢复调度阻塞。探测工作池固定为 4 个线程且没有等待队列，每项探测最多等待 2 秒；JDBC 查询设置超时，卡死探测不能无限创建线程。超过 90 秒未采样时返回 `OUT_OF_SERVICE`，清除旧数量和容量值，组件统一标记为未核实。

数据库健康需要实际查询成功，同时展示 Hikari 活跃、空闲、等待及连接上限；等待连接产生告警。后台统计覆盖异步任务、运行中的补偿、已到保留截止时间的对象清理、文件写入、重命名、工作副本、向量清理与重建失败。人工处理统计包含收件箱、治理确认/撤销冲突及持久化操作意图。停用账号的积压仍会进入全局统计；用户相关字段不会进入统计结果或指标标签。

桌面存储探测实际完成临时文件写入、同步、读取与清理，拒绝缺失目录及链接/重解析目录链。桌面无需 Redis。服务端探测访问配置的 MinIO bucket 并核对版本控制，任何访问失败或版本控制关闭均报告故障。

## 容量与备份配置

- 桌面自动采样本地文件库所在卷。Web/NAS 设置 `COFFER_STORAGE_VOLUME_PATH`，其路径必须属于实际 MinIO 数据卷；不能用后端容器的临时系统盘替代。如果由一键脚本新启动本机 MinIO，脚本自动使用该实例的数据目录；复用已有或远程实例时由部署配置明确指定实际数据卷。
- 默认容量阈值为可用空间少于 512 MiB 或少于总容量的 5%。通过 `COFFER_MIN_FREE_BYTES`、`COFFER_MIN_FREE_PERCENT` 修改。低容量使 readiness 故障；未配置的容量报告 `UNKNOWN` 并告警，不捏造容量值。
- 设置 `COFFER_BACKUP_RECEIPT` 指向备份作业输出的完成回执。回执最多 16 KiB，包含 `completedAt`、`verified`、64 位十六进制 `sha256` 和正数 `sizeBytes`；不记录备份文件路径。
- 完成实际备份后，执行 `scripts/write-backup-receipt.ps1 -ArchivePath <备份文件> -ReceiptPath <回执文件>`。脚本在禁止并发写入的读取句柄上计算 SHA-256，使用备份文件修改时间作为完成时间，并先写临时回执再替换。重新校验旧备份不会刷新其完成时间。
- 默认 48 小时后告警，可用 `COFFER_BACKUP_MAX_AGE_HOURS` 修改。缺失、异常、未来时间或过期回执都会被识别。备份故障产生告警，不阻断当前文件使用；未配置时明确显示未核实。
- 回执由可信备份作业维护并受宿主机权限保护。此处验证备份新鲜度及完成校验的证据，不创建真实备份，也不替代 R35/R42 的整库恢复演练。不要为消除告警制作虚假回执。

`COFFER_BACKLOG_WARNING_COUNT` 默认 100，`COFFER_BACKLOG_MAX_AGE_MINUTES` 默认 30。阈值绑定时校验合法范围，避免负值或零值掩盖真实故障。

## 主密钥轮换

轮换入口为 `GET/POST /api/admin/runtime/key-rotation`，服务层再次校验有效管理员；POST 同时受到会话与 CSRF 保护。接口不接收或返回密钥明文。

1. 备份现有数据库、文件与旧密钥。在维护窗口暂停写入及处理任务，确保没有仍使用旧主密钥的应用实例。
2. 配置新的 `COFFER_SECRET_KEY`，将旧值放入 `COFFER_SECRET_PREVIOUS_KEY`，重启应用。当前与上一把密钥可以解密；新写入只使用当前密钥。
3. 管理控制台执行“校验并轮换全库凭据”。程序覆盖复合主键的用户模型凭据、停用账号、遗留全局凭据、含 ownerless 行的运行端点以及所有执行快照，每页读取 200 条。
4. 所有非空密文都必须通过认证，包括已经标记为当前密钥的密文。错误指纹标签不会绕过重新加密。更新、完成核对和事件记录处于同一事务；坏密文、并发冲突或超时会整体回滚。
5. 成功响应返回校验数、更新数、旧密钥待重包数和当前密钥指纹。确认待重包数为 0，备份轮换后的数据库与新密钥，再移除上一把密钥并重启，恢复业务。

轮换 SQL 超时 5 秒，事务上限 110 秒，前端等待上限 120 秒。超时/连接失败不会显示成功，应重新查询状态与核对事件，不能依据旧页面移除旧密钥。新版本按 `v1:<key-id>:<ciphertext>` 写入并兼容读取遗留无前缀密文。prod/desktop 缺失主密钥时拒绝启动。

## 日志、错误与保留

- Console 与滚动日志统一采用固定事件码转换器，完全排除动态消息、参数、MDC、异常正文、堆栈及 cause；未登记的模板输出 `EVENT_RECORDED`。保留时间为 30 天，单文件 10 MiB，总量上限 200 MiB。
- 生产禁用 SQL/绑定参数日志、模型 SDK 请求与响应正文日志、HTTP access log、调试测试接口、H2 Console、Swagger/Knife4j UI 与文档、Actuator env/loggers/metrics 等管理出口。OpenAPI 仅在纯 `dev` 环境提供，不能在 prod/desktop 访问。
- 全局错误与控制器参数错误使用固定提示，不回传输入值、文件 ID 或原始异常。保留 `Result` 包装的旧接口，错误 HTTP 状态码与 `Result.code` 同步；前端对 HTTP 错误及遗留业务错误均按失败处理。
- 启动时立即清除所有旧模型诊断中的正文、回复、会话标识、模型名及错误详情，包括 ownerless/停用账号。每日清理 30 天前的模型诊断、180 天前的账号审计与轮换事件、90 天前已恢复告警；活跃告警不会按恢复保留期删除。
- 管理页面采样失败时清除旧正常数据；普通用户故障横幅展示原因和恢复动作。轮询在卸载/换账号时停止，返回结果遵守既有会话边界。
