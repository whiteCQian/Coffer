# R35 桌面备份、恢复与升级验收

日期：2026-10-09。依赖 R30–R34。本轮按用户要求在本环境恢复样本；用户明确确认没有独立介质，暂不进行该项验收。同一 SSD 上的 C:/D: 分区不会被标成独立介质。

## 整套加密备份

管理员面板提供备份，启动页提供恢复与升级。主进程先验证管理员、暂停业务代理、正常停止自己的后端，再由维护进程持有数据/正文库双锁。口令仅通过 IPC 和子进程 stdin，不能在命令参数、环境、偏好或日志中保存。

H2 使用 SQL `BACKUP TO` 事务一致性命令，不复制正在运行的 `.mv.db`。包同时包含数据库、所有 owner 的正文/inbox/work/quarantine/lost-found、配置、原主密钥以及 UUID/格式标识。密码哈希、模型配置、台账、未完成任务、解析正文和数据库记忆都在 H2 快照内。来源文件持只读锁并核对大小、完整 mtime、附加身份和 SHA-256；外部编辑器仍占用或来源变化则拒绝。

`.cofferbackup` v1 使用 PBKDF2-HMAC-SHA256（600,000 次，随机 salt）和 AES-256-GCM；按 1MiB 独立认证分块，绑定 header/块序号并认证最终块，内存有界。ZIP、文件名、配置和原密钥全部加密，目标介质不写明文归档。错误口令、篡改、错序、截断及缺失最终认证块均拒绝。

发布前执行完整加密读回验证：包内每项文件 hash/大小、必需密钥/标识、H2 版本、全表结构/行数/排序内容指纹、账号归属、正式正文、已发布未登记正文、未关闭副本，以及加密配置能否用原主密钥解密。清单/新鲜度回执本身不会被当作恢复成功。

标准备份检查真实物理盘及网络目标，目标不能与数据库/库位于同一设备；未知设备证据不提升为成功。管理员可明确选择本机加密快照，但结果 independent=false，界面显示独立备份待完成。后续有独立设备时应重新执行标准备份及读回验证。

## 新目录恢复

只恢复到不存在或空的新目录，不覆盖已有数据。先在受限本机暂存目录认证、校验全部内容，再同盘提交发布；必需密钥/正文缺失、数据库指纹不一致或目标非空时不会出现替代空库。

保留账号 ID、原密码哈希、原主密钥及库/目录 UUID。仅在整套内容通过认证后，重写实际库根目录，并对确实匹配正式版本/hash 的待保存基线重新绑定新机器文件身份。收件箱历史行保留，只重新绑定精确当前快照/mtime 时区；旧浏览器会话清理，恢复后重新登录。未完成台账和任务保持原事实，由既有启动对账恢复，不自动标记为已完成。

## 升级回滚

R34 明文升级复制分支已停用，旧启动开关不能再生成明文升级副本。离线升级先生成并读回验证整套加密回滚包，保留受限的已验证还原暂存数据，再运行 Flyway。

持久 journal 绑定原数据根、实际库根、暂存及其指纹，记录 MIGRATING / AWAITING_HEALTH / ROLLING_BACK。普通启动拒绝混合数据；新后端只有匹配备份 ID 的健康检查可启动，健康确认后清理暂存并保留加密包。DDL 或新后端健康失败恢复整套旧数据；进程中断后可验证暂存并重放事务，不能用新空库替代。较旧安装包拒绝降级写入。本机回滚包不替代独立介质备份。

## 操作与重跑

安装用户可用管理员面板和启动页。离线 CLI 需先关闭 Coffer 与外部文档，使用捆绑 JRE，口令以安全提示读取：

```powershell
scripts/desktop-backup.ps1 -Action snapshot -InstallDirectory <程序目录> -DataDirectory <数据目录> -DestinationDirectory <本机快照目录>
scripts/desktop-backup.ps1 -Action backup -InstallDirectory <程序目录> -DataDirectory <数据目录> -DestinationDirectory <独立设备目录>
scripts/desktop-backup.ps1 -Action verify -InstallDirectory <程序目录> -Archive <加密包> -TargetDirectory <已存在的本机临时验证父目录>
scripts/desktop-backup.ps1 -Action restore -InstallDirectory <程序目录> -Archive <加密包> -TargetDirectory <空新目录>
scripts/verify-desktop-backup.ps1 -MavenPath <mvn.cmd> -JavaPath <java.exe>
```

外部实际库传 `-LibraryDirectory`。`verify` 的 TargetDirectory 为已存在的本机临时验证父目录，原目录内容保留；`restore` 为实际新数据根，必须为空或不存在且父目录存在。CLI 属于本机 OS 拥有者的整套维护权限，浏览器/业务用户没有任意路径维护入口。口令遗失不能通过重生成主密钥恢复旧包。

机制依据 [H2 BACKUP 官方说明](https://h2database.github.io/html/commands.html#backup)；[H2 Backup 工具文档](https://h2database.com/javadoc/org/h2/tools/Backup.html) 区分了离线文件工具和在线 SQL 一致性命令。
