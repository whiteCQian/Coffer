# R14 模型目标与内容日志隔离验收

## 实现合同

普通用户分别维护模型模式、三种能力端点及凭据。提交上传、重试、对话、整理预览、重新分析、向量重建、语义标签联想前，界面展示实际端点与模型名称，并明确说明敏感或未识别内容也会发送。服务端要求匹配当前配置版本的明确授权；缺失、配置已变化均返回 428，不启动模型请求。

确认后生成 owner 绑定的不可变配置快照，密文包含当时的端点和凭据。文件、上传任务、整理批次、向量重建和聊天消息保存快照 ID；异步线程和查询分支显式传播，重启后的上传任务从数据库加载。旧任务缺失授权快照时失败并要求用户重新确认。修改当前配置不会改变已提交任务的目的地。

收件箱自动导入采用单独的持续授权；设置页显示已授权目标，并支持重新授权与撤销。撤销阻止后续导入，已提交任务仍按原快照处理。关键词自动补全只做本地匹配，语义联想必须主动点击并确认。

API 端点仅允许配置清单中的 HTTPS 主机和 443 端口。LOCAL 限制主机、端口和标准模型路径；默认端口为 11434、1234、8000，扩展由部署环境 `COFFER_LOCAL_MODEL_ALLOWED_PORTS` 指定。拒绝 URL 凭据、查询参数、片段和路径穿越。使用显式 JDK 模型传输，禁止 HTTP 重定向。回归发现旧 Spring SDK 适配器会覆盖请求工厂并恢复重定向，已替换，不能再使用原实现宣称阻断。

模型 SDK 关闭请求/响应日志及内部重试日志。适配器将供应商异常转换为无原始 cause 的固定错误。诊断不持久化正文、回答、会话标识、供应商返回的模型名称或原始异常；只展示用量、耗时、结果和固定错误类别。设置页可查看、分页、删除个人诊断。30 天后删除，专门的仅删除维护任务覆盖停用账号。管理员无诊断或模型配置访问权。

## 主密钥轮换

API Key 是用户数据，部署主密钥仅用于 AES-GCM 加密。新密文格式包含版本与派生 key ID；兼容既有无前缀密文。主密钥不得提交到代码库或输出到日志。

1. 安全备份数据库和现有主密钥；生成新的高熵主密钥。
2. 将原主密钥设置为 `COFFER_SECRET_PREVIOUS_KEY`，新密钥设置为 `COFFER_SECRET_KEY`，重启服务。
3. 每个普通用户在设置中执行“重新加密我的模型凭据”，原子重写其凭据、端点密钥、任务快照密文。
4. 所有账号完成后才能撤除 previous key；停用账号未完成时仍须安全保留旧密钥。此实现不允许管理员解密或代办用户凭据。提前撤除会使旧快照不可读取，不会自动改用新目标。

## 已执行验证

`ModelPrivacyIntegrationTest` 使用真实 Spring 授权代理、H2/Flyway V20、JDBC 会话、模型适配器及两个本地 HTTP 模型端点，验证：旧任务固定目的地和密钥；过期/缺失授权零调用；跨 owner 快照拒绝；管理员 HTTP 403；持续导入授权撤销；受限 URL 零调用；307 重定向不转发任何内容；带标记正文和密钥不进入错误或应用日志；诊断隔离删除及停用账号保留期。

专项测试连同 `SecretCryptoServiceTest`、`ModelCallLoggerTest`、`ModelCallLogCleanupTaskTest` 共 15 项通过。前端 TypeScript 检查与 Vite 生产构建通过。全量业务回归在继续补齐，结果以最终执行计划为准。

后续全量后端回归：275 项，0 失败、0 错误（JDK 25.0.3/Maven 3.9.16）。本机真实 MySQL 启动并完成 V16–V21 迁移；未连接真实外部模型，也未将启动检查视作 R50/R51 三环境验收。

未以这些测试替代真实外部模型、MySQL、NAS 或桌面验收。主机允许列表是部署信任边界；生产仍须用网络出口规则约束允许主机的 DNS/IP，当前没有 DNS 地址钉扎。
