# R12 服务层与后台任务授权

本次在现有未提交工作区上重做授权边界，保留业务流程；同时修复 R10 的账号管理服务授权及 R11 的模型凭据实体主键。没有清理开发数据库、旧对象或备份。

## 授权规则与实现

- 请求身份来自服务端 JDBC 会话。普通用户可进入私有业务 API；管理员只可进入账号管理及 `/api/admin/operations` 数字汇总。`/api/auth/**` 保留两种角色的账号操作入口。
- 私有业务服务使用 `OwnerOnly`。每次边界检查账号仍为启用的 USER，认证主体与 owner 必须一致；传入的持久实体也必须属于当前 owner。账号管理服务独立验证实际认证管理员，不能靠伪造方法参数取得权限。
- `OwnerRepositoryFactoryBean` 在 Spring Data 创建代理时装入授权拦截器，覆盖全部 19 类私有 Repository 的继承、派生、JPQL、原生查询及批量操作。检查不依赖普通 AOP 是否能匹配 Spring Data 的内部实现。
- Hibernate discriminator 继续约束派生/JPQL 查询。`OwnerJpaRepository` 的主键和引用读取显式包含 owner 条件；拒绝跨 owner 的游离实体保存、伪造生成主键更新及跨账号删除。原生 SQL 的 `ownerId` 参数必须等于当前账号。
- 同一 EntityManager/事务禁止切换 owner；关闭 open-in-view。匿名 owner 0 仅用于账号初始化等非内容数据，不得读取/写入私有 Repository。
- 不存在与跨用户资源统一抛出 `ResourceNotFoundException`，HTTP 404 且正文为 `资源不存在`。管理员访问私有 API 返回 403；未登录返回 401。列表和筛选导出允许返回空集合，但不返回他人条目。
- MinIO 的上传、读取、stat、签名、复制、删除分别校验当前 `users/{owner}/` 命名空间和固定 bucket；复制两端均检查。拒绝旧匿名路径、其他 owner、空路径段、反斜杠、控制字符及 `.`/`..`。持久删除/补偿意图登记时也检查对象路径。

## 后台执行

- 上传、归档、撤销、索引唤醒事件携带服务端 owner。`OwnedJobAspect` 校验事件 owner 与执行上下文，执行时重新验证账号；worker 仍须在该 owner 下读取持久任务/操作记录。事件不是绕过数据库所有权检查的授权凭证。
- 上传提交从已落库 AsyncTask 读取 owner，再提交执行器；去除上传门面与管道的双重异步。向量重建修复同类自调用绕过异步代理的问题。
- 启动恢复读取持久任务：PENDING 且文件存在则重新提交；中断的 PROCESSING 变为可重试 FAILED；缺失文件变为明确失败。不从上一次 HTTP ThreadLocal 恢复任务。
- 定时任务只有显式 `OwnerScheduled` 标记才逐启用普通账号执行。管理员、停用账号不进入内容处理循环；某账号失败不阻止后续账号。治理恢复、向量恢复与上传恢复使用同一账号枚举规则。
- 线程池传播只作为执行上下文；所有异步边界继续校验持久资源。正常完成、异常和 CallerRuns 均恢复原线程上下文。混合检索的公共线程池也显式绑定/恢复 owner。
- 停用账号的待执行任务保留、不执行；重新启用后可在下次启动恢复扫描重新提交。运行中任务的通用租约、周期性补投及崩溃一致性仍属于 R21，不能据此声称已经完成 R21。

## R10/R11 配套修正

- 创建、停用、启用、重置账号和读取账号/审计列表在 AccountService 内检查真实管理员；改密检查调用者身份。停用会撤销已有 JDBC 会话。
- 模型凭据原 SQL 主键为 `(owner_id, provider)`，实体却只声明 provider，现改用独立生成 id，保留 owner/provider 唯一约束；新增 H2/MySQL V18，不修改已执行迁移校验和。
- H2 验证了全新 V1–V18 和含双账号同 provider 数据的 V17→V18 升级。本轮随后已在本机 MySQL 实际启动应用并运行 V16–V21，包含 V18；同时验证了 V16 对真实 Hibernate 索引名的兼容修复。该启动验证不包含清理旧数据或 fresh/upgrade 完整矩阵；R11 存量清理和 R51 三环境验收仍未关闭。

## 人工验收与边界

1. 创建管理员、普通用户 A/B。A 上传文件并生成任务、预览和归档记录，保存对应 ID。
2. B 请求这些文件详情/正文/任务/预览/归档 ID，尝试重命名、删除、重试、撤销；应拒绝且 A 的资源不变。B 的列表/台账导出不得包含 A 的标记。
3. 管理员访问私有入口应为 403；`GET /api/admin/operations` 只能包含计数，不能包含文件名、路径、任务 ID、摘要或错误正文。
4. 停用 A，旧会话失效，后台不再调度 A；保留待执行记录。重启、恢复启用后核对任务在原 owner 下继续处理或进入可重试失败。
5. 交替执行 A/B 任务、重启治理补偿、使一个账号任务失败，核对另一账号继续工作，无上下文残留。

向量重建是用户私有操作，入口改为 `POST /api/vector/reindex` 和 `GET /api/vector/reindex/{jobId}`；旧 `/api/admin/vector` 不再提供内容任务入口。

本记录不替代 R13 的完整 Agent/引用矩阵、R14 的远端内容授权、R20/R23 的本地存储/Range、R21 的统一恢复状态机或 R51 的三环境故障注入；也不代表仓库全部历史匿名测试和整套 CI 已通过。
